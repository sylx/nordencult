# M007: 戦闘の拡充（攻撃の汎用化・新兵種・魔法・拠点兵器・CPU）

norden-battle の戦闘に、新しい兵種（ゴーレム・ドラゴン・ベヒーモス・ブレイン・上級魔術師）、ランツクネヒトの乱撃、魔法5種とクールタイム、状態異常、拠点兵器（要塞砲・ガンシップ・バリスタ・魔導台）、効果音、地形変化を加え、CPU の思考を入れてからバランスを調整する。

いまの攻撃は種類ごとに直書きになっている（`actions.ts` の `ActionId`、`combat.ts` の `COMBAT_DEFS`・`INDIRECT_KINDS`、`damage.ts` の `ATTACK_POWER`）。このまま 10 種類以上を足すと、1 つ足すたびに同じ数か所を直すことになる。そこで最初に、攻撃を「範囲のパターン・倍率・クールタイム・付く状態・演出」のデータとして書けるようにし、その上に兵種と魔法を載せる。

ゲーム本体（ルート）では、魔法は魔導書の装備、拠点兵器は都市の施設、ゴーレムなどは遺物の召喚で手に入る（`docs/designs/research_and_artifact_and_so_on.md`）。M007 ではそれらを battle-runtime が **入力として受け取れる** ところまでとし、battle-editor で試す。ルートからつなぐのは後続のマイルストーン。

複数のセッションで進めるための作業メモを兼ねる。タスクを終えたらチェックを付け、決めたことは「決定事項」、セッションの記録は末尾の「作業ログ」に追記する。

## 完了条件（通しのデモ）

battle-editor（`npm run dev:battle`）で:

1. 配備の部隊が、ゲームの騎士（名前・顔・統率・武力・知力・スキル）で並ぶ。エディタで部隊の騎士と兵種を選び直せる
2. 新しい兵種（ゴーレム・ドラゴン・ベヒーモス・ブレイン・上級魔術師）を配備でき、それぞれ自分の画像で出る
3. ランツクネヒトの乱撃で、周りの 6 HEX にいるユニットが敵・味方を問わずダメージを受ける
4. ドラゴンのブレスが直線 3 HEX に当たり、クロウは直接攻撃で反撃を受ける。ベヒーモスの光線は射程 3 で直撃と周りにダメージを与え、使った後はクールタイムの間は選べない（行動メニューに残りのターン数が出る）
5. ブレインは攻撃できず、兵数 1000 で硬い。軍団長にでき、殲滅されると軍団長部隊の全滅で決着する
6. 魔術師・上級魔術師が、持たせた魔法（チェインライトニング・フレイムランス・フロストノヴァ・アーススパイク・メテオフォール・サンダーフォール）を使える。魔法はクールタイム制で、範囲の HEX を選ぶ前に予測が出る
7. 混乱・凍結・感電が付き、情報札と部隊のウィンドウに出て、ターンが進むと切れる
8. 防衛側に要塞砲を持たせると、防衛側の番の終わりに拠点から 5 HEX 以内の敵（城内を除く）を撃つ。ガンシップは 3 ターンごとに全域の敵を撃つ。バリスタ・魔導台も（仕様を決めたうえで）動く
9. 入城の新しい決まりで、騎兵が 1 回の番で拠点に飛び込んで決着することが無くなる
10. 柵・土塁が戦闘中に置かれ、移動・防御に効く
11. 移動と各攻撃で効果音が鳴る
12. どちらかの軍（または両方）を CPU に任せると、CPU がすべての種類の行動から選んで戦う
13. 調整した数値で数戦して、決まった勝ち筋だけにならない

含む:

- battle-runtime: 攻撃の定義の汎用化、クールタイム、状態異常、新しい兵種と攻撃、魔法、拠点兵器（ターン終了時の処理）、入城の決まり、地形変化、効果音の口、CPU の思考

## 決定事項

### 順番

- 段階 0（データの輸入）は他から独立していて軽く、本物の騎士で試せるとテストプレイも楽しくなるので最初にやる
- 段階 1 で攻撃の汎用化を先にやる。追加する攻撃の大半（乱撃・ブレス・光線・魔法 5 種・要塞砲・ガンシップ）は同じ仕組みに載るため
- 段階 2 は 1 体だけ通す（ドラゴンとフレイムランス）。直線の範囲をユニットと魔法で使い回せるかを確かめてから、段階 3 で量産する
- 拠点兵器と入城の決まりは、どれも「ターン終了時」と「拠点」が絡むので段階 4 にまとめる
- **CPU は追加が一段落した後（段階 5）**。行動をすべて同じ形（汎用化した攻撃の定義と、既存の攻撃の予測）で評価する作りにすれば、兵種や魔法を足しても思考の側を直さずに済む
- **バランス調整は最後（段階 6）**。攻撃と状態異常が 10 種類以上入るので、途中で調整しても前提が崩れる。また、全部を自分で操作するテストでは戦略性を測れない。ただし明らかに壊れている数値は、気づいたときに直してよい
- 効果音はその演出が固まった段階で付ける。地形変化はマップを書き換える別の系統なので、最後の方（段階 4 の後）に回す

### データの輸入（段階 0）

- ルートのデータを読めない前提（norden-battle 単体で動かす）はもう無い。battle-editor はルートの `src/data/characterData.json` と顔のスプライトシートを直接読む
- 顔の切り出しはルートの `battleTroops.ts` の `portraitOf` と同じ（`imageInfo.sprite` と `faceRect`）
- 表示確認用の仮の部隊（`demoTroops`・`demoStatus`）は battle-runtime に残す（`BattleScreen` に部隊を渡さないときの既定。battle-editor はもう使わない）
- battle-editor の部隊は陣営ごとの「編成」（勢力・騎士・兵種・兵数・士気・軍団長）から作る（`battle-editor/src/gameKnights.ts`）。勢力を選ぶと、その勢力の騎士で当主が先頭、あとは統率の高い順に 8 部隊。既定はヴァルハルト家（攻撃側）とノルディス家（防衛側）で、今までの仮の勢力の名前と同じ
- 兵種は騎士の種別で率いられないものも選べる（新しい兵種を試すため。選択肢に「本来は率いない」と出す）
- ゲームの騎士には戦闘のスキルが無いので、スキルは表示確認用に編成の行の順で仮に配る
- 編成は「この編成で最初から」で反映し、localStorage に覚える（無い騎士を含むなら既定に戻る）
- セリフは部隊を率いる騎士が喋る（今までは口調のある騎士を順に割り当てていた）。ユニットごとに選び直せるのは前と同じ
- 上級魔術師（`wizard`）は段階 0 では魔術師と同じ性能（攻撃力・防御力・射程・行動力・サンダーフォール・迎撃）。雷の演出は兵種ではなく `magic` で選ぶようにした

## 設計

### 攻撃の定義（段階 1。M007-06 で決めたもの）

新しいファイル `battle-runtime/src/attacks.ts` に攻撃の定義を集める。いまの通常攻撃・一斉攻撃・突撃・サンダーフォール・迎撃の自動攻撃・ライフル兵の巻き添えもこの形に移す。

```ts
/** 攻撃の ID。行動メニューの行動の ID（ActionId）にもなる（いまの 'attack' などはそのまま） */
type AttackId = 'attack' | 'volley' | 'charge' | 'thunderfall' | 'interceptFire'; // 段階 2 以降に足していく

interface AttackDef {
  id: AttackId;
  name: string;
  cost: number;                 // 行動力（迎撃の自動攻撃は 0）
  power: number;                // 兵種の攻撃力に掛ける倍率（いまの ATTACK_POWER）
  aim: 'unit' | 'cell' | 'self';// 敵ユニットを狙う / 地点（空いた HEX も）を狙う / 狙わない（自分が中心。乱撃）
  range?: { min: number; max: number }; // 省略: 兵種の射程（COMBAT_DEFS の minRange..maxRange）
  shape?: Shape;                // 当たる範囲。省略: 通常攻撃・迎撃は兵種の形（ライフル兵は path）、ほかは single
  splashPower?: number;         // 目標以外に当たったときの倍率（省略: power。ベヒーモスの光線の周りなど）
  friendlyFire?: boolean;       // 範囲の味方にも当たる（ライフル兵の巻き添え・乱撃）
  indirect?: boolean;           // 隣でも反撃を受けない（サンダーフォール・迎撃）
  magic?: boolean;              // 省略: 兵種の magic。知力を使い、武力の軽減と迎撃の構えの影響を受けない
  cooldown?: number;            // 使った次の自分の番から、この回数の番は使えない
  inflicts?: { condition: ConditionId; chance: number; turns: number }[];
  fx?: StrikeFxKind;            // 演出。省略: 兵種の通常攻撃の演出
  special?: 'volley' | 'charge';// いまの特別な処理（一斉攻撃の味方の加勢・突撃の飛び出し）はそのまま残す
}

type Shape =
  | { kind: 'single' }                     // 目標だけ
  | { kind: 'path' }                       // 自分から目標までの直線上（目標の手前も）。隣より遠い目標は直線上だけ狙える（ライフル兵）
  | { kind: 'line'; length: number }       // 自分から目標の向きへ length HEX（目標の先も）。直線上だけ狙える（ブレス・フレイムランス）
  | { kind: 'burst'; radius: number }      // 狙った HEX とその周り radius HEX（光線・アーススパイク・メテオ）
  | { kind: 'around'; radius: number }     // 自分の周り radius HEX（aim: 'self'。乱撃）
  | { kind: 'chain'; jumps: number };      // 目標から近くのユニットへ跳ぶ（チェインライトニング。中身は段階 3）
```

- 兵種（`COMBAT_DEFS`）は、使える攻撃の一覧 `attacks: AttackId[]`、通常攻撃と迎撃の形 `shape`（いまの `pierce` の代わり）、通常攻撃の演出 `fx` を持つ。射程・`ranged`・`magic`・`moveAfterAttack`・`interceptHalts`・`unhaltable` はそのまま
- 兵種と攻撃の ID から、省略を埋めた定義を引く関数（`resolveAttack(type, id)`）を通して使う。魔法は段階 2 で `UnitStatus.spells` を兵種の一覧に足す（`attacksOf(unit, status)`）
- ルールの関数（three.js を使わない。テストする）:
  - `aimCells(map, unit, pos, attack)`: 狙える HEX（いまの `attackRange`。aim が unit なら、このうち敵のいる HEX が相手の候補）
  - `hitsOf(map, attacker, pos, aimed, attack)`: 当たるユニットと、それが目標（main）か範囲の巻き添え（splash）か（いまの `piercedUnits` の一般化）
  - 目標への結果はいまの `attackResult`（隣なら反撃あり）、巻き添えはいまの `pierceResult`（反撃なし・撃った側の士気は増減しない）と同じ計算
  - 予測（`attackForecast`）は目標と巻き添えのすべてのユニットについて出す
- `BattleApp`:
  - 予約した攻撃は `target: UnitData | null`（地点・自分を狙う攻撃は null）と `at: Offset`（狙った HEX）を持つ
  - 相手を選ぶ状態では、狙える HEX を塗り、カーソルを乗せた HEX で当たる範囲を別の色で塗って、予測を出す。aim が self の攻撃は選んだらすぐ予約する
  - 段階 1 で画面につないだのは aim が unit の攻撃だけ（いまの攻撃はどれも unit）。ルールの関数（`canAim`・`areaCells`・`splashUnits`）はすべての aim・shape に対応してテストしてある。cell・self を画面につなぐのは、それを使う最初の攻撃（乱撃・アーススパイクなど）を足すとき。そのとき `PlannedAttack.target` を null にできるようにして `at` を足す（いまは `id`・`target`）
  - 実行の結果（`ExecuteReport.attack`）は目標の結果と巻き添えの一覧（いまの `pierced`。名前を `splash` に変える）を持つ。戦闘記録・ステータス行・予測の窓をそれに合わせる
- 行動メニューの「攻撃」の 2 階層目は `attacksOf` から組み立てる（`MENU` の直書きをやめる）。クールタイム中の攻撃は灰色で残して「あと n ターン」と出す
- `strikeFx`・`interceptFx`・`attackArc` は兵種の分岐をやめて、解決した定義から引く

### クールタイム

- `UnitStatus.cooldowns: Partial<Record<AttackId, number>>`。攻撃を実行したときに `cooldown + 1` を入れ、その軍の番が始まるたびに 1 減らし、0 で消す（cooldown 1 なら、使った次の自分の番は使えず、その次から使える）

### 状態異常

- `UnitStatus.conditions: { id: ConditionId; turns: number }[]`。状態の定義（`CONDITION_DEFS`。名前・印・効果のフック）は `conditions.ts`
- 付くのは攻撃の `inflicts` から（確率で。同じ状態が付いていれば長いほうの残りターンにする）。付いたユニットの軍の番が終わるときに 1 減らし、0 で消す
- 段階 1 では混乱・凍結・感電の名前と印だけを定義し、効果は空にする（段階 3）。情報札に印、部隊のウィンドウに名前と残りターン数を出す。battle-editor に、選んだユニットに状態を付け外しする道具を足す（見え方の確認用）

### ターン終了時の処理（段階 4）

- `endTurn` で番を終えた軍の「ターン終了時の効果」（拠点兵器など）を順に実行してから次の軍へ渡す。演出の間は操作を受け付けない
- 拠点兵器は軍ごとの入力（`BattleData` か `loadMap` の引数に `fortWeapons: { side, kind, interval? }[]` のように渡す。形は段階 4 で決める）

### 効果音

- いまはメニューのクリック音（`data-sound`）だけで、鳴らし方は norden-ui 側にある。ゲームの効果音の素材は `src/assets/se/` にある。battle-runtime から演出の拍子に合わせて鳴らす口（`SoundId` と鳴らす関数を外から渡す形）を作り、battle-editor とゲームで同じ音を使う

### CPU（段階 5）

- 軍ごとに CPU に任せるかを選べる（`BattleApp` に `cpuTeams`）。CPU は軍の番になると、ユニットごとに「移動先 × 攻撃 × 目標」の候補を作り、攻撃の予測（与えるダメージ・受ける反撃・士気・殲滅・入城）から点数を付けて一番いいものを予約して実行する（まずは貪欲で、先読みはしない）
- 実行はプレイヤーの操作と同じ予約・決定の流れを通し、演出もそのまま出す
