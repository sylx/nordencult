# M002: 内政（都市の成長）

都市に騎士を担当として常駐させ（三國志IV方式）、毎ターンの自動処理で金・物資・兵士・人口が増え、施設を建てて都市が育っていく。その一巡と、侵攻（M001）との行き来を最低限の実装で通す。

複数のセッションで進めるための作業メモを兼ねる。タスクを終えたらチェックを付け、決めたことは「決定事項」、セッションの記録は末尾の「作業ログ」に追記する。

## 完了条件（通しのデモ）

1. 第1ターンの都市コマンド画面で、フルーエン（P012）の人口・Tier・商業・生産・備蓄物資・兵数・練度・施設スロットの使用数・領主が見える。HUD に勢力の金が出る
2. 「内政」→ 内政画面。フルーエンの騎士を領主（1人）と内政担当官（商業・生産・訓練・募兵に各2人まで）に割り当て、商業・生産・募兵にスライダで予算を割り当てると、次のターンの見込み（商業 +x〜y/ターン、練度 +z/ターン など）が出る
3. 同じ画面で施設を選んで着工する。金が引かれ、建設中の進捗（投入済み / 必要な物資）と完成までのターン数の見込みが出る
4. 募兵担当官に予算を割り当てると、次のターンに兵数が増え練度が下がる
5. 「ターン終了」→ 行軍フェーズ → 第2ターン。金が商業の合計だけ増え（俸禄が引かれ）、担当官が予算を使って商業・生産の基礎値と兵数が上がり、建設が進み、練度が上がり、人口が増える
6. 第2ターンにフルーエンを開くと、前のターンから変わった数値が演出つき（増分の表示・カウントアップ）で確かめられる
7. 何ターンか進めると施設が完成してスロットに入り、効果が出力に乗る。人口が閾値を超えると Tier とスロット数が上がる（デバッグで人口を足して確かめてよい）
8. 領主・内政担当官の騎士を侵攻画面で選ぶと「担当を外して出撃」になり、予約すると担当が外れる。予約を取り消すと担当に戻る
9. 侵攻に出した兵は出発した都市の兵数から引かれ、物資と金を消費する。戦後、兵は騎士と一緒に入城・帰還する
10. CPU 勢力の都市も同じ処理で育つ（担当は初期の領主がそのまま領主になるだけ）

## スコープ

含む:

- 都市の状態（人口・基礎の商業と生産・備蓄物資・兵数・練度・施設・建設中・担当・担当官の予算）と、勢力の金
- 都市のマスターデータの刷新（`agriculture` の廃止、初期値の追加）と norden-data の拠点エディタの対応
- 施設のマスターデータと norden-data の施設エディタ（画像の管理を含む）
- 毎ターンの内政処理（金 → 担当官の内政 → 物資と建設 → 兵士と練度 → 人口と Tier）と、その結果の記録（演出用の差分）
- 担当の割り当て・解除、担当官の予算の割り当て、建設の着工・中止、募兵
- 侵攻との兼ね合い: 担当の騎士の出撃、出撃で兵数・物資・金を消費、戦後の兵の移動
- 輸送の基盤（状態の操作関数とテストまで）
- norden-ui: 都市概要の表示、内政画面、成長の演出、侵攻画面での担当の表示

含まない（後続のマイルストーン）:

- 輸送の画面（M002 は操作関数だけ）
- CPU の思考（担当の割り当て・予算・建設・募兵をしない。初期の領主のまま自然に育つだけ）
- 研究・探索・商人（購入・売却）のコマンド
- 金が足りないときの罰（俸禄の未払い・離反など）。M002 は金がマイナスにならないよう操作を止めるだけ
- 傭兵の出現の効果（施設の効果の種類としてだけ持つ）
- 戦闘での兵の損耗の反映（battle 側が残兵を返せるようになったら。下記「兵の出入り」）
- 人口の減少・Tier の降格、食料の概念
- セーブ・ロード、勝利・敗北条件

## 設計

### 状態

```ts
type CityTier = 1 | 2 | 3

interface CityConstruction {
  buildingId: string
  /** 完成に必要な物資（ハンマー）。着工時のマスターの値を写す */
  requiredSupplies: number
  investedSupplies: number
}

type OfficerRole = 'commerce' | 'production' | 'training' | 'recruitment'
/** 金を使う役職 */
type FundedRole = Exclude<OfficerRole, 'training'>

interface CityAssignments {
  governor?: CharacterId
  /** 役職ごとに2人まで */
  officers: Partial<Record<OfficerRole, CharacterId[]>>
  // 研究・探索などの担当は後続で足す
}

interface CityState {
  population: number
  /** 基礎の商業・生産（初期値はマスター。担当官が上げる） */
  market: number
  production: number
  storedSupplies: number
  troops: number
  /** 0..MAX_MORALE */
  troopMorale: number
  /** 建設済みの施設（スロットの順） */
  buildings: string[]
  construction: CityConstruction | null
  assignments: CityAssignments
  /** 担当官の予算（役職ごとに 0〜1000。割り当てたときに国庫から移す） */
  affairsBudget: Partial<Record<FundedRole, number>>
}

interface GameState {
  // …M001 のもの（cityMorale は消す）
  cities: Readonly<Record<CityId, CityState>>
  /** 勢力の国庫 */
  gold: Readonly<Record<FactionId, number>>
  /** 直前の内政処理の結果（演出用）。都市ごとの前後の値と出来事 */
  lastEconomy: EconomyReport | null
}

interface EconomyReport {
  turn: number
  /** 勢力ごとの金の収入・支出 */
  factions: Record<FactionId, { income: number; salary: number; before: number; after: number }>
  cities: Record<CityId, {
    before: CitySnapshot
    after: CitySnapshot
    /** 担当官が使った金と上げた値（商業・生産の基礎値、兵数、練度） */
    affairs: Partial<Record<OfficerRole, { spent: number; gain: number }>>
    /** 施設の完成・Tier の上昇など */
    events: EconomyEvent[]
  }>
}
```

`CitySnapshot` は人口・Tier・商業（実効値）・生産（実効値）・備蓄・兵数・練度・建設の進捗。都市概要の演出は `before` → `after` を見る。

マスター（`src/data/city.ts`）:

- 最初の施設は 6〜8 種（市場・工房・兵舎・訓練場・倉庫・港・神殿 など）。数値は仮

### 内政処理（`runEconomy`）

`src/game/economy/` に置く。純粋な関数で、都市ごとの計算（`cityOutput(state, cityId)`）を都市概要・内政画面の見込み表示と共有する。

1. **補正**: 領主から商業・生産・成長の倍率、施設から各値の補正、担当官から役職ごとの能力 X を求める（処理の前の値で計算する）
2. **金**: 勢力ごとに、自勢力の都市の実効商業 × `GOLD_PER_MARKET` を合計して国庫に足す。所属する騎士の俸禄（`SALARY`。仮に一律）を引く
3. **担当官の内政**: 商業・生産・募兵の担当官が予算から 80〜150 の乱数の金を使う（役職ごとに独立して振る）。商業・生産は基礎値に足す（次の処理から実効値に乗る）。担当官がいない・予算が無い役職は飛ばす
4. **物資と建設**: 実効生産を求める。建設中なら進捗に足し、`requiredSupplies` に届いたら完成（スロットに入れ、余りは備蓄へ）。建設中でなければ備蓄に足す
5. **兵士と練度**: 兵がいれば練度 +1（自然上昇）＋ 訓練担当官の訓練。上限 `MAX_MORALE`。そのあと募兵担当官の新兵が加わり、練度が加重平均で下がる
6. **人口**: 実効商業・領主・施設から成長量を求めて足す
7. **Tier**: 人口が閾値（5,000 / 15,000）を超えたら Tier を上げる（スロット 2 / 4 / 6）。出来事に記録する

実効値と補正（仮。定数は `src/game/economy/balance.ts` にまとめ、テストで値を固定しない）:

- 実効商業 = 基礎商業 × (1 + 領主の補正 + 施設の補正)、生産も同じ形。基礎商業・生産は `CityState` の値（担当官が上げる）
- 領主の補正: 商業は政治、生産は政治と知力、成長は魅力から。能力 50 で 0、100 で +25% 程度。性格タグの補正は表で持つ（M002 は 2〜3 個だけ）
- 担当官の能力 X（2人なら合算）: 商業・生産 = (政治×2 + 知力) / 3、訓練 = (武力×2 + 統率) / 3、募兵 = (魅力×3 + 武力) / 4
- 商業・生産の基礎値の上昇 = max(1, 消費 × X/100 × 0.033)（四捨五入）。消費 115・X 160 で +6 程度
- 訓練 = max(1, X × 0.2)。X 160 で +32/ターン
- 募兵 = 消費 × X/100（切り捨て）。消費 115・X 160 で +184 人
- 人口の成長: 実効商業に比例し、人口が大きいほど伸び率が下がる（例: `population × 0.5% × 実効商業 / 400` に上限）
- 募兵コマンド（金で即時。画面はまだ）: 1ターンに募兵できる上限 = 実効生産 × 5（`soldierPool` を置き換える）× 軍事担当・施設の補正。1人あたり金 `RECRUIT_GOLD`。新兵の練度は `RECRUIT_MORALE`（仮に 20）で、全体の練度は兵数の加重平均で下がる

### 兵の出入り

- 侵攻の予約で、部隊の兵数の合計を出発都市の `troops` から引く（予約の取消で戻す）。予約の兵数の上限は都市の兵数になる（`soldierPool` は使わない）
- 出撃は兵1あたり物資 `SORTIE_SUPPLIES`・金 `SORTIE_GOLD` を払う。足りなければ予約できない
- 戦後: 攻撃側の勝利なら兵は目標の都市へ入る（練度は兵数の加重平均で混ざる）、防衛側の勝利なら出発都市へ戻る。損耗は battle 側が部隊の残兵を返せるようになるまで反映しない（全数が戻る。M002-24 で確認）
- 占領した都市の元の兵・備蓄・施設はそのまま新しい所属の物になる（仮）
- 輸送: `transport(state, from, to, { troops, supplies })`。自勢力の街道でつながった都市へ即時に移す。練度は加重平均。画面は後続

### 担当と侵攻の兼ね合い

- 侵攻画面の騎士カードに担当（領主・内政担当官）のバッジを出す。担当の騎士も選べ、選ぶと「担当を外して出撃」と分かる表示にする
- 予約したときに担当を外し、予約に `releasedAssignments` として記録する。予約を取り消したら、その都市の担当が空いていれば戻す
- 騎士が都市を離れたら（入城・退却・在野）担当から外れる。戻った（帰還）騎士の担当は戻さない
- 担当の騎士が予約中かどうかは、内政画面でも「出撃予約中」と出す

### UI（norden-ui）

- **都市概要**（`CityCommandScreen` の都市情報ウィンドウ）: 人口と Tier、商業・生産（実効値と基礎値）、備蓄物資、兵数と練度、施設スロット（施設の画像・空き）、建設中の進捗、領主。農業の欄は消す
- **HUD**: 左上の `FactionBar` に勢力の金（と次のターンの収支の見込み）・総生産・総兵力と都市の切り替え
- **内政画面**（`DomesticScreen`）: 画面いっぱいのウィンドウ。都市コマンド画面に重ね、ツールバーの「内政」で開閉する
  - 都市の現状: 領主（交代）、商業・生産・練度・新兵の練度のバー（領主・施設の補正を基礎値に積む。担当官の見込みは注記）
  - 建設: スロットの一覧（建設済み・建設中・空き）、建てられる施設の一覧（必要な物資・金・効果・完成までのターン数の見込み、建てられない理由）、着工・中止・中断・取り壊し・アップグレード
  - 内政担当官: 役職ごとに2人の枠（顔・名前・適性）、商業・生産・募兵の予算のスライダ（0〜1000、国庫の残りまで）、次のターンの見込み（商業 +x〜y/ターン（金 80〜150）など。予算が0なら「予算なし」）。枠を押すと右に適性の高い順の騎士一覧
- **募兵画面**（`RecruitScreen`）: 兵数を選び、金・兵数・練度の前後を出す
- **成長の演出**: 新しいターンに入って初めて都市概要を開いたとき、`lastEconomy` の `before` → `after` で数値をカウントアップし、増分（+120 など）を出す。施設の完成・Tier の上昇は短い通知にする。都市ごとに一度見たら出さない（見たかどうかはゲームの状態ではなくホストの UI の状態に持つ）
- 画面の追加は `norden-ui/docs/screens.md` の手順に従い、カタログ（デモ）にも載せる

## 未決事項・後続の候補

- Tier の閾値 5,000 / 15,000 と初期人口（3,000〜20,000）の釣り合い。今のデータでは Tier1 が 4 都市、Tier3 が 3 都市（15,000・18,000・20,000）で、残り 24 都市が Tier2 になる

- 基礎の商業・生産を人口に合わせて伸ばすか（M002 は担当官が予算を使って上げるだけ）
- 担当官の係数（0.033・0.2）と予算の乱数（80〜150）の釣り合い。訓練は X 160 で +32/ターンと速いので、数ターン進めて見直す（M002-27）

- 備蓄物資を建設に足す操作（建設を早める）
