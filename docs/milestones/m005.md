# M005: 傭兵（契約・独立採算）と放浪の騎士

金で契約する傭兵を、正規兵とは別の独立した部隊として実装する。都市のコマンドで契約し、自前の兵で編成・戦闘に加わり、月額を払い続ける限り使える。契約が切れれば市場に戻るか、回復中になる。その一巡を最低限の実装で通す。設計の元は `docs/designs/mercenary_and_drifters.md`。

あわせて、今は `cityId`・`factionId` が null なだけの「在野」を、どこかの拠点に居続けて各地を移動する「放浪」に置き換え、放浪の騎士の扱いを決める。放浪の騎士の登用は探索といっしょに実装するので、M005 では状態・移動・データ・デバッグ表示までとする。

遺物の使い道（施設化・装備・召喚）は M005 の後に回す。召喚部隊は「兵の補充が効かない独立した部隊」なので、M005 の独立採算の仕組みを使える。

複数のセッションで進めるための作業メモを兼ねる。タスクを終えたらチェックを付け、決めたことは「決定事項」、セッションの記録は末尾の「作業ログ」に追記する。

## 完了条件（通しのデモ）

1. 第1ターン。フルーエンの都市コマンドの「傭兵」が押せ、傭兵画面が開く。フルーエンと隣の都市にいる傭兵（樽盾団など）が、傭兵団の名前・騎士・兵科・兵数・契約金・月額・いる都市付きで並ぶ。2つ以上離れた都市の傭兵は出ない
2. フルーエンに酒場を建てると2つ先の都市の傭兵まで、傭兵ギルドにすると全拠点の傭兵が出る。敵の都市にいる傭兵も契約できる
3. プライドの高い傭兵（ランツクネヒトなど）は、金があっても契約できず、理由が出る（友好度の数値は見せない）
4. 傭兵と契約すると、その場で契約金が減り、都市の騎士一覧に傭兵が加わる（印付き）。そのターンから命令できる
5. 傭兵は内政の担当官・領主になれない。移動はできるが、選ぶと単騎移動が押せなくなり、ツールチップに「傭兵は単騎移動できません」と出る。輸送の担当にはなれる
6. 侵攻の編成に傭兵を加えられる。兵数と兵科は傭兵のもので変えられず、都市の兵は減らない。傭兵は軍団長になれず、傭兵だけでは出撃できない。防衛の編成も同じ
7. 戦闘では傭兵の部隊を通常の部隊と同じように動かせる。退却は必ず成功し（失敗の確率が0と出る）、全滅しても捕縛されない。退却先が無い軍では退却を選べない
8. 戦闘で減った傭兵の兵は戦闘のあとも傭兵のもので、都市の兵に混ざらない。毎ターン最大兵力の10%ずつ回復する
9. 全滅した傭兵は、退却先の有無にかかわらず契約が切れて回復中になり、傭兵業界の友好度が下がる
10. 毎ターンの内政処理で月額が払われる（勢力の経済の見込みに出る）。金が足りなければ契約が切れ、通知が出る
11. 契約から6ヶ月は更新料を求められない。6ヶ月を過ぎるとランダムで求められ、ターンの初めに通知が出て、「更新する」か「契約を打ち切る」かを選ぶ。更新すると、また6ヶ月は求められない
12. 傭兵画面の「契約中」から契約を打ち切れる。兵が減った傭兵を打ち切ると確認が出て、友好度が下がる。その傭兵は回復中になり、市場から消え、回復し終えると市場に戻る
13. 雇われていない傭兵は進行フェーズごとに隣の拠点へ移ったり留まったりする（回復中も）。デバッグコンソールで居場所を確かめる
14. 領主のいない都市が攻められると戦闘なしで奪われる。そこの傭兵は捕まらず隣の自勢力の都市へ撤退し、領主にはならない。撤退先が無ければ契約が切れる
15. 勢力が健在のまま退却先が無くなった騎士は、放浪にならず、部隊の兵を失って君主のいる拠点に帰ってくる（戦闘の結果の画面に出る）
16. 勢力を滅ぼすと、その勢力の騎士は最後の拠点から放浪を始め、滅ぼした勢力を怨恨勢力として覚える（デバッグコンソールで確かめる）。放浪の騎士の一覧は画面には無い

## スコープ

含む:

- 傭兵のマスターデータ（最大兵力・プライド）と norden-data の編集
- 傭兵の状態（兵数・契約）と、傭兵業界の友好度（画面には出さない）

- 在野を放浪に置き換える（居所・怨恨勢力）。騎士データの勢力の修正（省略＝都市の勢力をやめる）と、放浪の開始・怨恨勢力の設定

- battle-runtime: 捕縛されない部隊

含まない（後続のマイルストーン）:

- 放浪の騎士の登用（探索かランダムイベント。探索の実装時に実装する。怨恨勢力の判定もそのとき）
- CPU の傭兵の契約。CPU の手番はまだターンを渡すだけなので、傭兵を雇うのはプレイヤーの勢力だけ
- 情報＞傭兵（`mercenaryInfo`。押せないまま）
- 傭兵を地図に出すこと
- 遺物の使い道（施設化・装備・召喚）

## 決定事項

### 傭兵のデータと状態

| 項目 | 決定 |
| --- | --- |
| 傭兵とは | `Character.mercenaryInfo` を持つ騎士。`isMercenary(id)` で見分ける |
| 傭兵のデータ | `mercenaryInfo` に `maxSoldiers`（最大兵力。1000まで。`MAX_SOLDIERS` と同じ）と `pride`（プライド。1〜5）を足す。`fee` が契約金 |
| 傭兵の状態 | `GameState.mercenaries`（傭兵の id ごとの兵数と契約）。雇われていなくても持つ。最初は全員、最大兵力で市場にいる |
| 雇われた傭兵 | `CharacterState` は普通の騎士と同じ（`cityId`・`factionId` が雇い主の都市と勢力）。だから都市の騎士一覧・移動・編成の既存の処理に乗る |
| 雇われていない傭兵 | `cityId`・`factionId` は null で、居所は `roaming` に持つ（放浪の騎士と同じ）。`cityId` を null のままにするのは、`charactersIn` などの「都市に仕えている騎士」の処理に入れないため |
| 回復中 | 状態は持たず、「契約が無く、兵数が最大兵力より少ない」ことをそう呼ぶ（`isRecovering`）。回復し終えれば自動で市場に戻る |
| 開始位置 | `characterStart.json` の `cityId` が最初の居所。今は捨てている（`setup.ts`）ので `roaming` に入れる。傭兵の開始に勢力は書けない（書いてあれば検査のテストで落とす） |
| ヴェイラ（080） | 開始位置が無いのは設定ミス。サルビア（P006）に置く。「砂漠の向こうから来た」という設定に合わせた南の都市で、ほかに傭兵がいない |
| 月額 | 契約金の1/6。端数は切り上げ |

### 契約

| 項目 | 決定 |
| --- | --- |
| 契約の場所 | 都市コマンドの「傭兵」（`mercenary`）から開く傭兵画面。自勢力の都市で、手番のときだけ |
| 契約の成立 | その場で国庫から契約金を払い、開いている都市の騎士になる。傭兵のいる都市からの距離に関係なく、そのターンから命令できる |
| 契約できる範囲 | 開いている都市から街道で n 個先までの拠点にいる傭兵。酒場もギルドも無ければ n = 1、酒場があれば 2、傭兵ギルドがあれば全拠点。施設はその都市のものだけを見る。拠点の支配者は関係ない |
| 施設の判定 | `tavern`・`guild` の id で判定する。`etc` の文言はそのまま残す（M004 の技術の文言と同じ扱い）。ギルドは酒場のアップグレードなので、施設の効果の種類は増やさない |
| 契約できない傭兵 | 範囲外と回復中の傭兵は一覧に出ない。金が足りない・友好度が足りない傭兵は一覧に出して、理由を出す |
| 金額の確定 | 契約金と月額は契約のときの友好度で決まり、契約の間は変わらない |
| 兵科 | キャラクターの種別で固定する（`defaultUnitType`）。騎士→騎兵、狩人→弓兵、魔術師→魔術師、ライフル兵→ライフル兵、砲兵→砲兵、ランツクネヒト→ランツクネヒト。編成で変えられない |

### 傭兵業界の友好度

| 項目 | 決定 |
| --- | --- |
| 持ち方 | 勢力ごとの数値（`GameState.mercenaryStanding`）。-100〜100、最初は 0。どの画面にも数値を出さない |
| 上がるとき | 契約で +5。内政処理ごとに、勢力の酒場1つにつき +1、傭兵ギルド1つにつき +2 |
| 下がるとき | 兵が減った傭兵との契約が切れたとき -10（打ち切り・更新の拒否・未払い）。傭兵が全滅したとき -15。兵が満ちている傭兵の打ち切りでは下がらない。敗戦で契約が切れるだけなら下がらない |
| 値段への効果 | 倍率 = 1 − 友好度 / 100 × プライド × 0.1。プライド5・友好度40で ×0.8、プライド5・友好度 −50 で ×1.25。端数は切り上げ。契約金・月額・更新料に効く |
| 選り好み | 友好度が `(プライド − 3) × 20` より低いと契約できない。プライド1は −40、3は 0、4は 20、5は 40 |

### 月額・更新料・打ち切り

| 項目 | 決定 |
| --- | --- |
| 月額の支払い | 内政処理で、給金と同じく勢力の収入のあとに払う。契約の次の内政処理から払う |
| 払えないとき | 傭兵の id の順に払い、払えない傭兵の契約が切れる（払える傭兵が後にいれば、その分は払う）。通知を出す（`MercenaryUnpaid`） |
| 更新料の発生 | 契約または更新から6ヶ月たつまでは求められない。6ヶ月からは内政処理ごとに 1/3 の確率で求められる。更新すると数え直すので、また6ヶ月はかからない |
| 更新料の額 | 契約金の半分（友好度の倍率つき） |
| 更新料の選択 | ターンの初めの通知（`MercenaryRenewal`）で「更新する」か「契約を打ち切る」を選ぶ。閉じるだけでは済まない（Enter・Esc では閉じない）。金が足りなければ「更新する」は押せない |
| 打ち切り | 傭兵画面の「契約中」から、手番のときにいつでもできる。金は戻らない。移動・輸送・侵攻の予約中は打ち切れない（理由を出す） |
| 契約が切れたときの居所 | いた都市が居所になる。移動中なら今いる都市（`route[0]`）、戦闘で切れたなら戦場の拠点。市場に出るか回復中かは兵数で決まる |
| 移動中に契約が切れたとき | 移動から傭兵が抜ける。ほかの騎士が残っていなければ移動が消え、運んでいた兵と物資は失われる（勢力が都市を失ったときの移動と同じ） |

### 独立採算

| 項目 | 決定 |
| --- | --- |
| 傭兵の部隊の兵 | `MercenaryState.soldiers` のもの。出撃でも帰還でも都市の兵は増減しない。都市の兵で補充できない |
| 回復 | 内政処理ごとに最大兵力の10%（端数は切り上げ）。契約の有無にかかわらず同じ |
| 編成の兵数 | 傭兵の今の兵数で固定。全滅すると契約が切れるので、契約中の傭兵の兵が0になることはない |
| 傭兵の練度 | 固定の `MERCENARY_MORALE`（70）。都市の練度と混ざらない。`BattleArmy.morale` はそのままで、`battleTroops` が傭兵の部隊だけ置き換える |
| 給金 | `SALARY` の人数に傭兵を数えない（月額を払うため） |

### 戦略画面と編成

| 項目 | 決定 |
| --- | --- |
| 内政 | 領主にも担当官にもなれない（`assignmentProblem`・`successorLord`・戦後の `appointGovernor` で除く） |
| 移動 | できる。領主のいない拠点に移っても領主は不在のまま |
| 単騎移動 | 移動に傭兵が含まれるとできない（`moveOrderProblem`）。チェックボックスは押せず、ツールチップに「傭兵は単騎移動できません」と出す。単騎移動を選んだまま傭兵を加えると、単騎移動を外す |
| 輸送 | 担当になれる。帰りの単騎は輸送の決まりなので例外とする |
| 軍団長 | なれない。`commandRank` ではなく `canCommand` で判定し、`orderProblem`・`defenseProblem`・`leadingKnight`・`createBattle` で傭兵を除く |
| 傭兵だけの出撃 | できない。軍団長になれる騎士が要る（`invadeFromProblem`・`orderProblem`）。軍団長は都市の兵を率いるので、都市の兵が0なら今までどおり出撃できない |
| 予約のあとに軍団長がいなくなったとき | 進行フェーズで軍団長になれる騎士が残っていなければ、その侵攻は取りやめる（`armyOf` が null を返す） |
| 防衛 | 編成に加えられる（`defenseKnights` に入る）。CPU の `defenderArmy` でも、都市の兵を傭兵に分けない |
| 戦闘の無い占領の判定 | 今までどおり。領主が不在か都市の兵が0なら戦闘にならず、傭兵だけでは防衛しない |

### 戦闘と戦後処理

| 項目 | 決定 |
| --- | --- |
| 捕縛 | 傭兵は捕縛されない。battle-runtime の `UnitStatus` に捕縛されない印を足し、退却の失敗と殲滅の捕縛の確率を0にする |
| 退却 | 退却先が無い軍では退却できない。これは今の作り（軍ごとの `retreats`）のままでよい |
| 全滅 | 退却先の有無にかかわらず契約が切れ、戦場の拠点を居所に回復中になる。友好度は下がる。戦闘が報告する落ち延びた先（`BattleWipeout.to`）は傭兵には使わない |
| 領主のいない都市が奪われたとき | 設計資料は「近くの都市に撤退、無ければ解除」（戦略画面）と「単に契約を解除」（戦後処理）の2通りに書いている。隣接の自勢力の都市があれば撤退し、無ければ契約が切れる、に統一する。普通の騎士の退却先（`refuge`）と同じ決め方 |
| 敗戦で都市に残った傭兵 | 同じく `refuge` へ撤退し、無ければ契約が切れる。普通の騎士が君主のもとへ帰る場合に、傭兵は契約が切れる |
| 残った部隊の兵 | 傭兵の部隊の兵は、勝っても負けても傭兵のもの。退却先が無くて契約が切れても兵は失われない |
| 領主 | 退却先や入城先に領主がいなくても傭兵は領主にならない |
| 勢力の滅亡 | 傭兵は契約が切れ、最後の拠点が居所になる。怨恨勢力は持たない。`FactionDestroyed.knights` には入れない |
| 戦闘の結果の画面 | 契約が切れた傭兵を `CharacterMove.kind: 'released'`（契約解除）で出す |

### 退却先が無い騎士

| 項目 | 決定 |
| --- | --- |
| 対象 | 勢力が健在で、退却先が無い騎士。全滅して落ち延びる先が無いときと、都市が奪われて隣接の自勢力の都市が無いとき。今の `wander`（在野）の代わりで、放浪にならない |
| 帰る先 | 君主のいる拠点（`rejoinCity`）。君主が捕虜のときや、君主の拠点が勢力のものでないときは、戦場からいちばん近い自勢力の都市（`nearestCity`） |
| 騎士の部隊の兵 | 0 になる。失われ、帰る先の都市の兵には入らない |
| 帰り方 | 戦後処理のその場で着く。退却と同じ扱いで、移動の時間はかからない |
| 君主自身 | 同じ決まりで、いちばん近い自勢力の都市へ帰り、そこの領主になる（君主が退却したときと同じ） |
| 領主 | 帰った先に領主がいなければ、退却と同じく任命する（`appointGovernor`） |
| 傭兵 | この決まりの対象ではない。退却先が無ければ契約が切れる |
| 戦闘の結果の画面 | `CharacterMove.kind: 'rejoin'` で出す |

### 放浪の騎士

| 項目 | 決定 |
| --- | --- |
| 放浪とは | どの勢力にも仕えていない騎士。`cityId`・`factionId` が null で、居所を `roaming` に持つ。今の「在野」をすべてこれに置き換える |
| 放浪になるとき | 勢力の滅亡（居所は最後の拠点）。勢力の都市が無くなった移動（居所は今いる都市）と、勢力の無い脱走（居所は逃げた都市）も同じ |
| 怨恨勢力 | `CharacterState.grudge`。勢力の滅亡で、滅ぼした勢力が入る。滅亡の戦闘で先に勢力を離れた騎士（`served` の全員）にも入れる |
| 登用 | M005 では実装しない。探索の実装時に、`grudge` の勢力からはイベント自体が起きないようにする |
| 捕虜 | 今のまま。勢力が滅んだ捕虜は勢力の無い捕虜のままで、放浪にしない |
| 移動 | 進行フェーズの初めに（`runEscapes` のあと）、雇われていない傭兵と放浪の騎士が 1/2 の確率で隣の拠点のどれかへ移る。行き先は等確率で、支配者は関係ない |
| 一覧 | 画面には出さない。デバッグコンソールだけ |
| 最初から放浪 | 新しいフラグは足さない。開始に勢力が無く（`factionId` の省略）、傭兵でもない騎士が放浪で始まる。`cityId` が居所で、`grudge` に怨恨勢力を書ける |

### 傭兵の処理（`src/game/mercenaries/`）

純粋な関数。画面の見込みと共有する:

- `isMercenary(id)`・`isRecovering(state, id)`
- `mercenaryReach(state, cityId)`: 開いている都市から届く距離
- `mercenaryMarket(state, cityId)`: 契約できる範囲の傭兵（回復中を除く）
- `contractPrice(state, factionId, id)`: 友好度を入れた契約金と月額
- `hireProblem(state, cityId, id)`・`hireMercenary(state, cityId, id)`: 契約
- `dismissProblem(state, id)`・`dismissMercenary(state, id)`: 打ち切り
- `endContract(state, id, at)`: 契約を切る処理。打ち切り・更新の拒否・未払い・敗戦・滅亡で共有する。騎士を `roaming: at` にし、移動から抜き、`contract` を null にする
- `decideRenewal(state, eventId, renew)`: 更新料の選択
- `mercenaryFees(state, factionId, available)`: 月額のうち払える分と、払えない傭兵（`treasuryForecast` と共有する）
- `runMercenaries(state, turn, random)`: 内政処理の最後。未払いの契約を切り、兵を回復し、施設の分の友好度を足し、更新料を判定する

### 放浪の処理（`src/game/roaming.ts`）

- `wanderer(at, grudge?)`: 放浪になった `CharacterState` を返す。`{ cityId: null, factionId: null }` と書いている箇所（`resolveBattle` の `move`・`destroyFaction`・`runMovements`・`escapeOf`）を置き換える
- `rejoinCity(state, factionId, at)`: 退却先が無い騎士の帰る先。君主のいる拠点、または `at` からいちばん近い自勢力の都市。勢力の都市が無ければ null（放浪になる）。`resolveBattle` では、奪われた都市を勢力のものとして数えない
- `runRoaming(state, random)`: 放浪の移動。`endFactionTurn` の `runEscapes` のあとに呼ぶ

### 既存の処理の変更

- `setup.ts`: `start.factionId` の都市の勢力での補完をやめる。傭兵は最大兵力の `MercenaryState` を作り、居所を `roaming` に入れる。勢力の無い騎士も `roaming`（と `grudge`）に入れる。`mercenaryStanding` を 0 で初期化する
- `queries.ts`: `canCommand`（傭兵でない）。`leadingKnight` は軍団長になれる騎士だけを見る。`soldiersLeft`・`unitsProblem` は傭兵の部隊の兵を都市の兵に数えない。`unitsProblem` は傭兵の部隊の兵数と兵科が、今の兵数と `defaultUnitType` のとおりであることを確かめる。`invadeFromProblem` は軍団長になれる騎士を求める
- `movement.ts`: `moveOrderProblem` に単騎移動の条件を足す
- `actions.ts`
  - `armyOf`: 傭兵の部隊は今の兵数と固定の兵科で、pool を使わない。軍団長になれる騎士が残らなければ null
  - `sumSoldiers` を都市の兵の分だけにする（出撃・入城・防衛）
  - `resolveBattle`: 傭兵を `captives` から除く。退却と残った部隊の兵を `addSoldiers` ではなく `mercenaries` に入れる。全滅の傭兵は `to` にかかわらず `released` にして `endContract` し、友好度を下げる。行き先が無い傭兵も `released`。普通の騎士は行き先が無ければ `rejoinCity` へ `rejoin` で帰り、勢力の都市が無ければ `wander` にする。`rejoin` の先を領主の任命（`appointGovernor`）と君主の入城の対象に足す。`appointGovernor` で傭兵を除く
  - `destroyFaction`: 傭兵は `endContract`、それ以外は `grudge: by` の放浪にする。`factionId` がもう null の騎士（`wander`）にも `served` から入れる
- `economy/runEconomy.ts`: `treasuryForecast` に月額を足す。最後に `runMercenaries` を呼ぶ
- `economy/domestic.ts`: `assignmentProblem`・`successorLord` で傭兵を除く
- `defense.ts`: `defenderArmy` は傭兵に今の兵数を持たせ、都市の兵は残りの騎士で分ける
- `src/scenes/battle/battleTroops.ts`: 傭兵の部隊の `morale` を `MERCENARY_MORALE` にし、捕縛されない印を付ける

## 未決事項・後続の候補

- `runMovements` の「勢力の都市が無い移動」に傭兵がいても契約は切らない。都市を失うのは戦闘だけで、そのときは `destroyFaction` が先に契約を切るので今は通らない。戦闘以外で都市を失う規則を足すときは `endContract` を通す
- 契約中の傭兵の更新料は、プレイヤーの勢力でなければ求めない（`runMercenaries`）。CPU が契約するようになったら判断といっしょに入れる
- 放浪の騎士の登用（探索・ランダムイベント）と、怨恨勢力の判定
- CPU の傭兵の契約と、CPU が雇ったときの更新料
- 情報＞傭兵の画面（契約中の一覧は傭兵画面にあるので、市場全体を見せるか決める）
- 勢力が滅んだ捕虜の扱い（今は勢力の無い捕虜のまま残り、脱走もしない）。解放されたら放浪にするか
- 傭兵が戦闘で経験を積むか（`MERCENARY_MORALE` は固定）
- 召喚部隊に独立採算の仕組みを使う（兵は自分のもの、自然回復のみ、内政に出ない）。傭兵との差は契約が無いこと
