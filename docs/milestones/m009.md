# M009: 遺物の使用（装備・施設・召喚）

修復済みの遺物を使えるようにする。いまは遺物を解体・修復・生産・法王府に依頼できるが、修復済みになっても「使い道はまだありません」と出るだけで、何にも使えない（`RelicScreen`）。

M009 では、遺物の 3 つの使い道（`RelicUse`: 施設・装備・召喚）をすべて作る。

- **装備**: 騎士は装備の枠を 2 つ持つ。ライフル・大砲を付けた騎士はライフル兵・砲兵を率いることができ、魔導書を付けた魔術師はその魔法を戦闘で使える
- **施設**: 施設の遺物（要塞砲・バリスタ・魔導台・ガンシップ）を持っていれば、その施設を都市に建てられる。建て終わると遺物は無くなる
- **召喚**: ドラゴン・ゴーレム・ベヒーモスの遺物を使うと、その魔物が名前の付いた 1 つの部隊（召喚ユニット）として勢力に加わる

戦闘の側（battle-runtime）は、魔法（`TroopInit.spells`）と魔物の兵種（`dragon`・`golem`・`behemoth`）を M007 で受け取れるようにしてある。M009 はそこへルート（ゲーム本体）からつなぐ。

複数のセッションで進めるための作業メモを兼ねる。タスクを終えたらチェックを付け、決めたことは「決定事項」、セッションの記録は末尾の「作業ログ」に追記する。

## 完了条件（通しのデモ）

ゲーム本体（`npm run dev`）で:

1. 遺物の画面で、修復済みのライフルを選んで「装備させる」を押すと、勢力の騎士の一覧が出て、選んだ騎士の空いた枠に付く。付けられない騎士（魔術師・傭兵など）は理由付きで選べない
2. 騎士の詳細ウィンドウに装備の枠が 2 つ出る。枠を押すと付けられる遺物の一覧が出て、付け替え・外すができる
3. ライフルを付けた騎士（魔術師以外）は、出撃の画面で兵種にライフル兵を選べる。大砲なら砲兵。外すと選べなくなる（もともとライフル兵・砲兵を率いる種別の騎士はそのまま）
4. 魔導書を付けた魔術師は、戦闘で対応する魔法を使える（例: 火の魔導書でフレイムランス）。知力が足りない魔術師には付けられない。サンダーフォールは魔導書が無くても使える
5. 修復済みのガンシップを持っていると、内政画面の建てられる施設にガンシップが出て「遺物：ガンシップを 1 つ使用」と書いてある。建て始めると遺物は「建設中」になり、中止すると戻る。建て終わると遺物は箱から消える
6. 遺物の画面で、修復済みのドラゴンを選んで「召喚」を押すと、HP・攻撃力・防御力が決まり、名前を付ける窓が出る。名前は入力でき、「自動」ボタンで名前の一覧から何度でも選び直せる
7. 召喚ユニットは、遺物の画面を開いた都市に、ID 991（ドラゴン）の立ち絵と顔で現れる。都市の騎士の一覧と詳細ウィンドウに HP・攻撃力・防御力が出る（統率・武力・知力は見せない）。種別は「召喚」
8. 召喚ユニットを出撃させると、その魔物の兵種の部隊として戦う。HP はドラゴン 600・ゴーレム 800・ベヒーモス 1000 で、都市の兵を使わない。軍団長にはなれない
9. 召喚ユニットは都市にいれば毎ターン HP が最大の 10% 戻る。内政の担当官・領主にはならない

コマンドラインで:

10. ルートの `npm test`・typecheck、norden-battle・norden-ui・norden-data のテストと typecheck が通る

## 決定事項

### ユーザーの要件（2026-11-12 にユーザーから）

装備品遺物の使用:

- 全騎士には装備スロットが 2 つある
- RelicScreen または騎士詳細ウィンドウで、遺物を装備できる
  - UI 的にはそれぞれ騎士一覧、遺物一覧が必要となるが、汎用的な作りにできればしてほしい（他でも使うかもしれない）
- 魔術師以外のキャラクターはライフル、大砲を装備可能
  - 元々の兵科に追加して、ライフルでライフル兵、大砲で砲兵をそれぞれ編成できるようになる
- 魔術師は魔導書を装備できる。それぞれ対応した魔導書でその魔法を使用することができる

召喚遺物の使用:

- RelicScreen で使用することで、それぞれ対応したモンスターがユニットとして加わる
- 召喚すると、ランダムで HP 以外の能力値が決定される。ユーザーには HP、攻撃力、防御力が見える（召喚ユニットも内部的に統率、武力、知力などのパラメーターがあり、それが決定されるという意味。政治、魅力は内政を担当することがないので、固定値（10））
- 召喚すると、名前をつける（テキスト入力）ことができる
  - 自動ボタンがついていて、名前リストから名前をつけることもできる。自動ボタンは何度でも押せる
- キャラクターグラフィックは特殊キャラクターの扱いになる。ID:991〜999 までのキャラクターで、ID:991 ドラゴン、ID:992 ゴーレム、ID:993 ベヒーモスの順。立ち絵、顔グラフィックなどはこれを使う（characterData.json に該当 ID を追加する時は、norden-data で新規 ID が 991 未満になるように norden-data のエディタを調整すること）
- 他に設定が書いてあるかもしれないが、HP はそれぞれ、ドラゴン 600・ゴーレム 800・ベヒーモス 1000 である

### 装備（2026-11-12 にユーザーと決めたもの）

- **上級魔術師という兵種はルートに無いものとして進める**（battle-runtime の `wizard` は魔術師と画像が違うだけ）。万色の魔導書で魔術師が上級魔術師になることはしない
- **万色の魔導書**は、雷・火・水・土の 4 つの魔法（トールハンマー・フレイムランス・フロストノヴァ・アーススパイク）がまとめて使える
- **知力の制限を入れる**（遺物ごとの `equipment.minIntelligence`）。万色の魔導書は知力 90、星辰の魔導書（天体魔法）は知力 95 以上。火・水・土の魔導書は 70、雷の魔導書は 80（Claude が出した値をユーザーが OK）
- **同じ遺物（`relicId`）を 2 つの枠に付けられない**。ライフルと大砲を 1 つずつは付けられる（両方の兵種を選べる）
- **傭兵は装備できない**
- **騎士が勢力を離れたら、付けていた遺物は元の勢力の箱に戻る**（捕縛・放浪・傭兵の契約の終わり）。捕らえた勢力のものにはならない

### 施設の遺物（2026-11-12 にユーザーと決めたもの）

- 施設の遺物を **持っていれば、その施設を建てられる**（`Building.requiredRelic`。いまは遺物を管理していないので満たされることが無い）
- 建てられる施設の欄に「遺物：ガンシップを 1 つ使用」のような注釈を出す
- **建設中は遺物がロック（建設中）になる**。箱には残るが、ほかの施設の建設に使えない。**中止すると戻る**（ロックが外れる）
- **建て終わると遺物は勢力の箱から消える**。施設を取り壊しても遺物は戻らない
- **建設中に都市を奪われたら、建設も遺物も失われる**（修復中の遺物が都市と一緒に失われるのと同じ）

### 召喚（2026-11-12 にユーザーと決めたもの）

- **能力値の幅**: 統率・武力・知力はどれも 60〜90 の一様な乱数（魔物ごとに変えない）。政治・魅力は 10
- ~~**攻撃力・防御力は全体の強さで見せる**~~ → M009-30 で数字を並べて見直し、**1 撃あたり**（battle-runtime の基本攻撃力・基本防御力）にした（「段階 4 で決めたこと」）
- **壊滅したら失われる**（遺物にも戻らない）
- **HP の回復**: 都市にいるときだけ、毎ターン最大の 10%
- **軍団長になれない**（軍団長は人の騎士）
- **勢力が滅んだら消える**（放浪しない）
- **種別の名前は「召喚」**（一覧などに出す種別。`CharacterType` の `summon`）
- 召喚ユニットの数の上限は無し。名前は 12 文字まで

### 計画で決めたこと（段階 0 で一度確かめる）

- **大砲（`field_gun`）は装備にする**。いまの遺物データでは使い道が「施設」になっているので「装備」に変える（大砲を求める施設は無い）。要塞砲（`cannon`）は施設のまま
- **雷の魔導書はトールハンマー**。M007 でチェインライトニングをトールハンマーに変えたので、遺物（`grimoire_chain_lightning`）と技術（雷魔法）の説明を直す。遺物の ID は変えない（勢力の初期の遺物などで使っているため）
- **ベヒーモスの HP は 1000**。battle-runtime（`MAX_SOLDIERS` の 1200）と battle-editor（`SOLDIERS`）を 1000 に揃え、M007 の決定事項の 1200 は上書きする
- **召喚の元になるキャラクター（991〜993）はゲームに配置しない**。画像と既定の値を持つだけの型紙で、`characterStart.json` に入れない。ゲームの中の召喚ユニットは、召喚のたびに作る別の ID を持つ（同じドラゴンを 2 体召喚できる）
- **召喚ユニットは召喚した都市に現れる**（`RelicScreen` を開いた都市）。そこに仕える騎士と同じように、移動・出撃ができる
- **召喚ユニットは装備の枠を持たない**（要件の「全騎士」は人の騎士）
- **能力値を決めるのは召喚したとき**。名付けの窓は能力値が決まった後に出し、閉じても能力値は変わらない（窓を開き直して能力値を引き直すことはできない）。名付けの窓に「やめる」は無く、「決定」で閉じる。名前を空にはできない
- **施設に使う遺物は箱の中から自動で選ぶ**（同じ遺物が複数あれば、ロックされていない最初のもの）

### 段階 0 で決めたこと（2026-11-12）

- **991〜993 の画像は仮**（ユーザーと決めた）。norden-data の書き出しは画像の無いキャラクターを除くので、いまは 130 グドルン・ベーアのセルを 3 体とも仮に割り当てて書き出した（`character-2.webp` の末尾）。召喚ユニットの画像ができたら norden-data で差し替えて「ゲームに書き出す」
- 型紙の能力は政治・魅力 10、統率・武力・知力 75（ゲームでは使わない。召喚したときに 60〜90 で決まる）
- 特殊キャラクターの ID の決まりはルートの `character.ts` に置く（`SPECIAL_CHARACTER_IDS`・`isSpecialCharacterId`・`nextCharacterId`）。norden-data の「＋ 新規」もこれを使う（norden-data にはテストの仕組みが無いので、テストはルートの `character.test.ts`）
- 遺物の効果の検査は `relicEffectProblems`（ルートの `relics.ts`）にまとめ、`relicDataProblems` と norden-data の遺物のエディタの両方が使う。norden-data の書き出しのサーバー（Vite の設定から読まれる）は `@game` の値を読めないので、効果の検査はエディタの警告（あると書き出せない）とルートのテストだけでする
- 検査に足したもの: 使い道と効果の食い違い・装備で兵種も魔法も増えない・騎士の率いる兵種でない（魔物・歩兵以外の不明な ID）・`SPELL_IDS` に無い魔法・魔術師以外の装備の魔法・型紙が 991〜999 でない／いない・召喚の兵種が魔物でない・HP が 1 未満・施設の遺物を求める施設が無い
- `DEFAULT_UNIT_TYPES.summon` は表を埋めるための仮（`infantry`）。召喚ユニットの兵種は段階 4 で `SummonState.unitType` から引く
- norden-data は `@norden/battle-runtime/rules`（と、それが読む `@norden/map-runtime/*`）を読めるようにした（`vite.config.ts`・`tsconfig.json`）

### 段階 1 で決めたこと（2026-11-13）

- `RelicItem.equippedBy.slot` は `0 | 1` でなく `number`（`EQUIPMENT_SLOTS` を変えても型を直さずに済むように）。枠の検査は `equipProblem` がする
- 付け外しの条件の「勢力に仕える騎士」は、勢力があり捕虜でも放浪でもない騎士。移動中・輸送中の騎士は付け外しできる（出撃の予約だけが不可）
- 同じ騎士の別の枠へ移すこともできる（`equipRelic` で付けている枠と違う枠を指す）。同じ枠には「装備しています」
- `equippableKnights` は、その遺物をいま付けている騎士を除く（付け替え先の一覧のため）
- `releaseEquipment(state)` は全勢力の箱を見て、箱の勢力に仕えていない騎士が付けている遺物を外す（1 か所で直す形）。呼ぶのは `resolveBattle` の最後（滅亡の後）・`endContract`・`runMovements`・`debugImprison`
- 魔法は `battleSpells(state, battle)` で騎士ごとにまとめ、`battleTroops(battle, spells)` に渡す（`BattleScene` で計算。進行フェーズには装備を変えられないので、戦闘の始まりのまま）
- CPU の防衛の編成（`defenderArmy`）は既定の兵種のままで、装備の兵種は使わない（CPU は遺物を使わない）。プレイヤーの防衛の編成は `KnightView.unitTypes`（`unitTypesOf(state, id)`）を通して装備の兵種を選べる
- デバッグコンソール: `relic list <勢力>` で遺物の ID と状態、`knight list [勢力]` を新設（兵種・装備）、`knight show` に兵種と装備

### 段階 2 で決めたこと（2026-11-13）

- 部品の置き場: `RelicRow`（`RelicRarity` も）・`EquipmentSlots` は `components/parts`、`PickerDialog`・`KnightPicker`・`RelicPicker` は `components/picker`
- `PickerDialog` は `body` に描く（騎士の詳細ウィンドウの中から開いても切られないように）。騎士の詳細ウィンドウは、選ぶ窓が開いているあいだ Esc で閉じない

- 遺物の画面の「装備させる」は、選んだ騎士の空いた枠（付けられる枠）に付ける。空きが無ければ入れ替える遺物を選ぶ窓を出す。装備中の遺物は「別の騎士に装備させる」と「外す」
- 装備の候補（`equipCandidatesView`）は勢力に仕える騎士すべて（傭兵も理由付きで出す）。いま付けている騎士は「装備しています」で選べない
- 他勢力の騎士の詳細にも装備の枠は見せる（「他勢力の騎士です」で押せない）。傭兵・捕虜・放浪には枠を出さない
- 遺物の効果は `RelicView.effects`（「ライフル兵を率いる」「魔法: フレイムランス」「知力 70 以上の魔術師が装備できる」）で、遺物の画面の説明の下と装備の枠に出す（枠には装備できる騎士の行を出さない）。魔法の名前は battle-runtime の `ATTACK_DEFS`

### 段階 3 で決めたこと（2026-11-13）

- 建設の作業は `BuildingWork`（`{ kind: 'building'; buildingId; relicItemId? }`）に分けた。`BattleReport.lostRelicWork` は `RelicWork | BuildingWork | null`（遺物を使う建設だけが入る）。結果の画面の言い方は「ガンシップの建設（遺物：ガンシップ）が都市とともに失われました」（`relicWorkLabel`）
- 見せるか（`buildingLocked`）は「修復済みのその遺物を持っているか」（ロックされているものも数える）。持っていても全部がほかの都市の建設に使われていれば、一覧には出し「遺物「バリスタ」はほかの都市の建設に使っています」で建てられない。壊れたものしか無ければ伏せたまま
- 法王府に依頼中の遺物は使わない（修復済みでないので、もともと当たらない）
- 建て終わりで遺物を消すのは `runRelics`（経済の処理の `buildingCompleted` のイベントに `relicItemId` を持たせる）
- 都市を奪われたとき、遺物は都市の元の持ち主（`state.cityOwners`）の箱から消す。滅亡で箱が移る前に消す
- 中断中も遺物はロックのまま
- 建設中の枠にも「遺物：ガンシップを使用中」を出す（`ConstructionView.relicNote`）。取消のツールチップに「使っている遺物はボックスに戻ります」
- 遺物の画面: 修復済みの施設の遺物は「内政画面で{施設名}を建てるのに使えます。建て終わると遺物は無くなります」。建設中は「{都市}で{施設名}の建設に使っています。建て終わると無くなります。内政画面で中止すると箱に戻ります」で、操作（献上のボタン）は出さない
- デバッグコンソール: `city fill <都市>` を新設（建設・修復・生産に要る物資を全部入れて中断も解く。次のターンの初めに完成）。`relic list <勢力>` に「建設中: 都市名」、`city show` の建設に遺物の ID

### 段階 4 で決めたこと（2026-11-13）

ユーザーと決めたもの:

- **士気は固定の 70**（傭兵と同じ値。`SUMMON_MORALE`）
- **俸禄は払わない**（俸禄の人数に数えない。いまは `SALARY` が 0）
- **単騎移動はできない**（傭兵と同じ）。普通の移動はできる
- **攻撃力・防御力**（M009-30）: 攻撃力は基本攻撃力（`basicAttack`）、防御力は **1 撃あたりの基本防御力**（`basicDefense`。出撃の画面と同じ物差しで、標準の部隊が 100）。HP を含めた「全体の強さ」にする案（標準の部隊の通常攻撃に何回耐えるか）と比べて、ユーザーが選んだ。魔物は攻撃に使う兵数が固定なので、攻撃力も防御力も HP では下がらない。士気 70 で、統率・武力 75 のドラゴンは 172 / 185、ゴーレムは 104 / 293、ベヒーモスは 158 / 185

実装で決めたもの:

- 召喚ユニットの ID は `summon-<serial>` で、ID だけで召喚ユニットと分かる（`isSummon`）。状態を見ずに済むので、`canCommand`・`citySoldiers` などはそのまま使える
- 傭兵と召喚ユニットを「自前の兵を持つ部隊」としてまとめた（`hasOwnSoldiers`・`ownSoldiers`・`ownMorale`）。`defaultUnitType`・`unitAbilities` は状態（`summons`）を受け取るようにした
- `characterOf(state, id)` は `src/game/summons/character.ts`（`summonCharacter` が型紙の画像に名前・能力・種別を重ねる）。置き換えたのは、軍・出撃の検証・戦闘の部隊（`battleTroops` の第 3 引数に `summons`）・戦闘のセリフ・画面の騎士（`knightView`・`knightName(game, id)`・`knightsLabel(game, ids)`）・戦闘の結果の画面（`KnightList` の `characterOf`）。内政・会話・傭兵は直引きのまま（召喚ユニットはデータに無いので、会話の配役に入らない）
- 勢力を離れた召喚ユニット（勢力が無い・捕虜・放浪）は `releaseSummons` が消す。`releaseEquipment` と同じ所（`resolveBattle`・`runMovements`・`debugImprison`）から呼ぶ。勢力の滅亡では `destroyFaction` が消し、`FactionDestroyed.knights` に入れない
- 戦闘の後: 壊滅した召喚ユニットは `BattleReport.lostSummons` に入れて消す（移動には入れない）。退却先が無く勢力の都市にも戻れないときも失われる（騎士なら放浪のところ）。結果の画面のために `BattleReport.summons` に戦闘の始まりの召喚ユニットを残す
- 領主の無い都市が奪われたとき（戦闘なし）、召喚ユニットは捕まらず、隣の自勢力の都市へ退く（傭兵と同じ）
- 回復は内政処理の最後（`recoverSummons`）。最大の 10% を四捨五入で足し、最大で止める
- 段階 4 の画面は仮: `knightView` は召喚ユニットに傭兵の印（`mercenary`。会社名「召喚」、兵数 = HP、士気 70）を付けて、出撃の画面で兵種と兵数を固定にしている。そのため都市の騎士の一覧では傭兵の欄に出て、出撃の画面で「傭兵は軍団長になれません」「傭兵の兵科と兵数は変えられません」と出る。段階 5（M009-34）で召喚ユニットの見せ方に変える
- 名前の一覧（`summonNames.json`）は仮に 12 個ずつ Claude が付けた
- battle-runtime: `@norden/battle-runtime/rules` から `basicAttack`・`basicDefense`・`STANDARD_UNIT`・`MAX_BASIC_DEFENSE`・`UnitPower` を読めるようにした（ルートの `summonStrength` が使う）
- デバッグコンソール: `relic summon <都市> <遺物>`、`summon list|show|hp|name`、`knight list` の装備の欄に召喚ユニットの HP

## 設計

### 遺物の効果

遺物ごとに、装備したとき・召喚したときに何が起きるかを持たせる。norden-data の遺物のエディタで編集できるように `relicData.json` に置く（`Relic` に足す）。施設の遺物は、施設の側（`Building.requiredRelic`）が遺物を指しているので、遺物の側には何も足さない。

```ts
interface Relic {
  // …いまのもの
  /** use が 'equipment' のもの: 付けられる騎士と、付けたときに増えるもの */
  equipment?: {
    /** 付けられる騎士の種別。'magician': 魔術師だけ、'nonMagician': 魔術師以外（傭兵・召喚ユニットはどちらも不可） */
    wearer: 'magician' | 'nonMagician'
    /** 付けるのに要る知力。省略: 制限なし */
    minIntelligence?: number
    /** 率いることができるようになる兵種（ライフル → rifleman、大砲 → artillery） */
    unitTypes?: UnitTypeId[]
    /** 戦闘で使えるようになる魔法（battle-runtime の SpellId） */
    spells?: SpellId[]
  }
  /** use が 'summon' のもの: 召喚ユニットの型紙 */
  summon?: {
    /** 画像と既定の値を持つキャラクター（'991'〜'999'） */
    characterId: string
    unitType: UnitTypeId          // dragon / golem / behemoth
    /** HP（戦闘の兵数。召喚ユニットの最大兵力） */
    hp: number                    // 600 / 800 / 1000
  }
}
```

| 遺物 | 種別 | 効果 | 知力 |
| --- | --- | --- | --- |
| ライフル `rifle` | 装備（魔術師以外） | ライフル兵を率いる | — |
| 大砲 `field_gun` | 装備（魔術師以外） | 砲兵を率いる | — |
| 火の魔導書 `grimoire_flame_lance` | 装備（魔術師） | フレイムランス | 70 |
| 水の魔導書 `grimoire_frost_nova` | 装備（魔術師） | フロストノヴァ | 70 |
| 土の魔導書 `grimoire_earth_spike` | 装備（魔術師） | アーススパイク | 70 |
| 雷の魔導書 `grimoire_chain_lightning` | 装備（魔術師） | トールハンマー | 80 |
| 万色の魔導書 `grimoire_prismatic` | 装備（魔術師） | トールハンマー・フレイムランス・フロストノヴァ・アーススパイク | 90 |
| 星辰の魔導書 `grimoire_meteor_fall` | 装備（魔術師） | メテオフォール | 95 |
| 要塞砲 `cannon`・バリスタ `ballista`・魔導台 `arcane_focus`・ガンシップ `gunship` | 施設 | 同じ名前の施設を建てられる | — |
| ドラゴン `dragon` | 召喚 | 991・dragon・HP 600 | — |
| ゴーレム `golem` | 召喚 | 992・golem・HP 800 | — |
| ベヒーモス `behemoth` | 召喚 | 993・behemoth・HP 1000 | — |

- 雷の魔導書を 80 にしたのは、トールハンマーがサンダーフォールの上位版で、4 つの元素のなかでは強いため
- `relicDataProblems` に、use と `equipment`・`summon` の食い違い（装備なのに `equipment` が無いなど）、`summon.characterId` が無いキャラクター、`spells` が `SPELL_IDS` に無いもの、施設の遺物なのにそれを求める施設が無いものを足す
- ルートが `SpellId` を使うので、`@norden/battle-runtime` の `SPELL_IDS` をルートのデータから読めるようにする（いまルートは battle-runtime を `src/scenes/battle` から使っている。`src/data` から型と定数だけ読む）

### 兵種（ルートの `unitTypes.ts`）

- `UnitTypeId` と `UNIT_TYPES` に `dragon`・`golem`・`behemoth` を足す（名前は battle-runtime の `UNIT_DEFS` と同じ）。人の騎士は率いない（`UNIT_TYPES_BY_CHARACTER_TYPE` には入れない）。`wizard` は足さない

### 装備（段階 1・2）

**状態**: 装備は勢力のアイテムボックスの遺物の側に持たせる（遺物は勢力のもの。騎士が勢力を離れたら外して箱に戻すだけで済む）。

```ts
interface RelicItem {
  // …いまのもの
  /** 装備している騎士と枠（0 か 1）。無ければ誰も付けていない */
  equippedBy?: { characterId: CharacterId; slot: 0 | 1 }
  /** 施設の建設に使っている都市（建設中のロック。段階 3） */
  buildingIn?: CityId
}
```

- `EQUIPMENT_SLOTS = 2`（`balance.ts`）
- 問い合わせ: `equipmentOf(state, characterId): (RelicItem | null)[]`（枠の順）、`equippableRelics(state, characterId)`（付けられる遺物）、`equippableKnights(state, itemId)`（付けられる騎士）
- 命令（`…Problem` で理由を返し、命令は `GameRuleError` を投げる。いまの遺物の命令と同じ形）:
  - `equipRelic(state, characterId, slot, itemId)`: 枠に付ける。枠が埋まっていれば前の遺物は箱に戻す（付け替え）。別の騎士が付けている遺物なら、その騎士から外して付ける（付け替えを 1 手で済ませる）
  - `unequipRelic(state, characterId, slot)`
- 付けられる条件（`equipProblem`）:
  - 自分の勢力の戦略フェーズの手番
  - 勢力に仕える騎士（捕虜・放浪は不可）。**傭兵・召喚ユニットは不可**
  - 遺物は修復済みで、使い道が装備。法王府に依頼中でない
  - 騎士の種別が `equipment.wearer` に合う（魔術師 ↔ 魔導書、魔術師以外 ↔ ライフル・大砲）
  - 騎士の知力が `equipment.minIntelligence` 以上（「知力 90 が必要です」）
  - もう一方の枠に同じ遺物（`relicId`）を付けていない
  - その手番の出撃の予約（`orders`）に入っている騎士は付け外しできない（予約した兵種が変わってしまうため）
- 騎士が勢力を離れたら外して元の勢力の箱に戻す: 捕縛（戦闘・都市の陥落）、放浪、傭兵の契約の終わり（傭兵は付けられないが念のため）、勢力の滅亡（箱ごと無くなる）。外す処理は 1 か所（`releaseEquipment`）にまとめ、勢力を離れる処理のそれぞれから呼ぶ。テストで「勢力に仕えていない騎士が付けている遺物は無い」を確かめる
- 解体・修復・法王府への依頼は壊れた遺物だけなので、装備中の遺物とはぶつからない

**兵種**: `unitTypesOf(characterId)` を `unitTypesOf(state, characterId)` にし、種別の兵種に、付けた遺物の `equipment.unitTypes` を足す（重なりは除く）。`defaultUnitType` は変えない（もともとの種別の既定）。

- 出撃の画面（`InvasionScreen`）・防衛の編成（`pendingDefense` のプレイヤーの編成・CPU の `defenderArmy`）・`queries.ts` の検証が新しい `unitTypesOf` を使う

**魔法**: `battleTroops` で、部隊を率いる騎士が付けた魔導書の `equipment.spells` を `TroopInit.spells` に渡す（重なりは除く）。battle-runtime は magic の兵種（魔術師）のときだけ使うので、魔術師が歩兵を率いれば魔法は出ない（いまの battle-runtime のまま）。間接の部隊（軍団長が率いる騎士のいない部隊）には渡さない。

- CPU の勢力の部隊も、付けていれば魔法を使う（CPU が付ける処理は作らない。デバッグコンソールで付けて試せる）

### 施設の遺物（段階 3）

- **建てられるか**（`buildingProblem`）: `requiredRelic` のある施設は、勢力の箱に、修復済みでロックされていない（`buildingIn` の無い）その遺物があれば建てられる。無ければいまと同じ「遺物「ガンシップ」が必要です」
- **見せるか**（`buildingLocked`）: 遺物を持っていなければいまと同じく伏せる（建てられる施設の一覧に出さない）。持っていれば出す
- **建て始める**（`startConstruction`）: 箱の中の使える遺物を 1 つ選び、`buildingIn` に都市を入れてロックする。建設の作業に、使った遺物を覚えさせる（`ConstructionWork` の `building` に `relicItemId?: string`）
- **中止**（`cancelConstruction`）: 覚えた遺物の `buildingIn` を外す
- **建て終わり**（経済の処理）: 覚えた遺物を箱から消す
- **都市が奪われたら**: 遺物を使っている建設は、建設も遺物も失われる（`resolveBattle` で、いまの `lostRelicWork` と同じく建設を消し、元の勢力の箱からロックされた遺物を消す。戦闘の結果に失われた建設として出す）。遺物を使わない施設の建設はいまのまま奪った勢力が続けて建てる
- 遺物の画面では、ロックされた遺物を「建設中（都市名）」と出す（`RelicView.status` に `'building'`）
- 内政画面の建てられる施設（`BuildOptionView`）に `relicNote`（「遺物：ガンシップを 1 つ使用」）を足し、施設の詳細・建設の欄に出す
- 修復済みの施設の遺物を遺物の画面で選んだときは、「内政画面で{施設名}を建てるのに使えます」と出す（「使い道はまだありません」の代わり）
- 技術の説明にある「〜を遺物なしで生産できる」は、遺物を生産できるという意味として、M009 では施設の側の決まりを変えない（遺物を生産してから建てる）

### 召喚（段階 4・5）

**型紙**: `characterData.json` に 991 ドラゴン・992 ゴーレム・993 ベヒーモスを足す（画像の位置・既定の名前。ユーザーが norden-data で画像を割り当てる）。

- `CharacterType` に `summon`（表示は「召喚」）を足す。`UNIT_TYPES_BY_CHARACTER_TYPE`・`DEFAULT_UNIT_TYPES` などの表に入れる（率いる兵種は空。召喚ユニットの兵種は遺物の `summon.unitType`）
- norden-data: `nextCharacterId` は 991 未満の ID の最大 + 1 にする（990 に達したら新規を作れないと出す）。キャラクターの一覧の絞り込みに「特殊（991〜999）」を足し、配置（`start`）の無いことを問題にしない

**状態**: 召喚ユニットは、ほかの騎士と同じく `GameState.characters` に入り（仕える都市・勢力を持つ）、能力値などは別に持つ。

```ts
interface GameState {
  // …いまのもの
  /** 召喚ユニット（ID は 'summon-<serial>'）。characters にも同じ ID で入る */
  summons: Readonly<Record<CharacterId, SummonState>>
}

interface SummonState {
  /** 型紙のキャラクター（'991' など）。画像はこれのもの */
  templateId: CharacterId
  /** 召喚した遺物（RELIC_LIST の id） */
  relicId: string
  /** 12 文字まで */
  name: string
  unitType: UnitTypeId
  /** 召喚したときに 60〜90 で決まる（SUMMON_ABILITY_RANGE） */
  leadership: number
  strength: number
  intelligence: number
  /** 政治・魅力は固定の 10（SUMMON_FIXED_ABILITY） */
  /** いまの HP（戦闘の兵数）と最大（遺物の summon.hp） */
  hp: number
  maxHp: number
}
```

- **キャラクターの引き方を変える**: いまは静的なデータ `CHARACTER_MAP[id]` を 44 か所で直に引いている。召喚ユニットはデータに無いので、`characterOf(state, id): Character | undefined` を作り、召喚ユニットなら型紙の画像に名前・能力値・種別 `summon` を重ねた `Character` を返す。召喚ユニットが通る所（`army.ts`・`queries.ts`・`movement.ts`・`prisoners.ts`・`battleTroops.ts`・`BattleScene`・`views.ts`・`KnightList` など）をこれに置き換える。内政・会話・傭兵など召喚ユニットが通らない所は直引きのまま残し、召喚ユニットを除く
- **召喚の命令**: `summonProblem(state, cityId, itemId)`・`summonRelic(state, cityId, itemId, random)`。遺物を箱から消し、能力値を乱数で決め、名前は名前の一覧から自動で付けて、都市に置く。返り値で新しい ID を返す。`renameSummon(state, id, name)` で付け直す（名付けの窓の「決定」。1〜12 文字）
  - 条件: 自分の勢力の戦略フェーズの手番・自分の都市・修復済みで使い道が召喚の遺物・法王府に依頼中でない
- **名前の一覧**: `src/data/summonNames.json`（型紙の ID ごとの名前の配列）。自動は、勢力の召喚ユニットの名前と重ならないものから無作為に選ぶ（尽きたら重なってもよい）
- **兵**: 召喚ユニットの部隊の兵数は自分の HP で、都市の兵を使わない（傭兵の自前の兵と同じ扱い）。出撃の兵数は HP の全部で固定
  - 戦闘の後: 生き残れば残った兵数が HP になる（都市の兵には入らない）。**壊滅したら失われる**（`summons` と `characters` から消す。遺物にも戻らない）。退却は残った兵数が HP になって退却先の都市へ
  - 回復: 経済の処理で、**都市にいる**（移動中・輸送中でない）召喚ユニットの HP が最大の 10% 戻る（最大まで）。兵の補充（募兵）は効かない
  - 捕縛されない（`TroopInit.uncapturable`。傭兵と同じ）。退却に失敗したときも捕まらない
- **できないこと**: 軍団長（出撃・防衛の軍団長に選べない。召喚ユニットだけの軍は作れない）・領主・内政の担当官・輸送の担当にならない。会話（`dialogue`）の配役に入らない。傭兵の市場・放浪に出ない
- **勢力が滅んだら消える**
- **戦闘**: `battleTroops` で、兵種は `unitType`、統率・武力・知力は召喚ユニットのもの、顔は型紙の画像、部隊の名前は召喚ユニットの名前、性格は無し（標準）

**攻撃力・防御力の表示**: 召喚ユニットは統率・武力・知力を見せず、HP・攻撃力・防御力を見せる。~~HP を含めた部隊全体の強さで出す。~~ → M009-30 で 1 撃あたり（基本攻撃力・基本防御力）に決めた（「段階 4 で決めたこと」。下の案は記録として残す）

- 攻撃力: その部隊が標準の部隊（`STANDARD_UNIT`）に通常攻撃したときのダメージ（battle-runtime の式。兵種の攻撃力・攻撃に使う兵数・統率と武力の補正）
- 防御力: HP を、標準の部隊の通常攻撃で受けるダメージで割ったもの（何回の攻撃に耐えるか）に係数を掛けて見やすくしたもの
- 細かい式と見せ方（係数・丸め）は M009-30 で数字を並べてユーザーと決める。式は battle-runtime から関数（`unitStrength(type, soldiers, leadership, strength, intelligence)` など）として出し、ルートはそれを呼ぶ（式を写さない）
- HP が減れば攻撃力・防御力も下がる（全体の強さなので）。魔物の攻撃に使う兵数は固定（`FIXED_ATTACK_SOLDIERS`）なので、攻撃力は HP では下がらないことがある

### 画面（段階 2・3・5）

**汎用の部品（norden-ui）**: 他の画面でも使えるように、一覧と選ぶ窓を分けて作る。

- `KnightPicker`: 騎士の一覧から 1 人（または複数）を選ぶ。顔・名前・種別・能力値の列、並べ替え、選べない騎士は灰色で理由を出す。中身は `KnightView` の配列と、行ごとの `disabledReason`・補足（例: 装備中の遺物）を受け取るだけで、ゲームの決まりを知らない
- `RelicPicker`: 遺物の一覧から 1 つを選ぶ。いまの `RelicScreen` の `RelicRow` を部品に切り出して使い回す（絵・名前・レアリティ・状態）。選べない遺物は理由を出す
- `PickerDialog`: 上の一覧を載せる窓（タイトル・決定・やめる。Escape で閉じる）。`KnightPicker`・`RelicPicker` のどちらも載せられる
- `EquipmentSlots`: 装備の枠 2 つ（付けた遺物の絵と名前、空き）。押すと選ぶ窓を開き、外すボタンを持つ

**遺物の画面（`RelicScreen`）**:

- 修復済みの装備の遺物: 「装備させる」（`KnightPicker` の窓。勢力の騎士。付けられない騎士は理由付き。知力の制限は「知力 90 が必要です」）。装備中なら「装備中（騎士名）」と出し、「外す」を足す。騎士の 2 つの枠が埋まっていれば、どちらと入れ替えるかを選ぶ
- 修復済みの施設の遺物: 「内政画面で{施設名}を建てるのに使えます」。建設に使っていれば「建設中（都市名）」
- 修復済みの召喚の遺物: 「{都市}で召喚」→ 召喚の名付けの窓
- `RelicView` に `status: 'equipped' | 'building'` と装備している騎士・建設中の都市の名前、装備の行動（`equip`・`unequip`）、召喚の行動（`summon`）の可否と理由を足す

**騎士の詳細ウィンドウ（`KnightProfileWindow`）**:

- 人の騎士: 能力値の下に `EquipmentSlots`。枠を押すと `RelicPicker` の窓（その騎士に付けられる遺物。ほかの騎士が付けている遺物は「○○が装備中」と出し、選べば付け替え）。手番でない・出撃の予約に入っている・傭兵などで付け外しできないときは枠を押せず、理由を出す
- 召喚ユニット: 能力値のチャートの代わりに HP・攻撃力・防御力。装備の枠は無い。略歴の代わりに召喚した遺物の説明
- `KnightView` に `equipment`（枠ごとの遺物の表示）と `summon`（HP・攻撃力・防御力）を足す。`CityInfoWindow` から装備の操作の口（`onEquip`・`onUnequip`）を通す

**召喚の名付けの窓（`SummonDialog`。norden-ui）**:

- 召喚ユニットの立ち絵、HP・攻撃力・防御力、名前の入力欄（12 文字まで）と「自動」ボタン、「決定」
- 「自動」はルートから渡す名前の候補の関数を呼ぶ（何度でも押せる）。名前が空なら決定できない

**出撃の画面（`InvasionScreen`）**:

- 召喚ユニットは兵種を選べず（1 つだけ）、兵数は HP（都市の兵の欄から引かない）。傭兵の自前の兵と同じ見せ方にそろえる。軍団長には選べない（理由を出す）
