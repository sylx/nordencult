# M001: プレイヤーの侵攻

戦略シーンのプレイヤーターンで騎士を選んで敵の拠点へ侵攻を予約し、行軍ののち戦闘シーンを呼び出し、その結果を戦略シーンに反映して次のターンへ進む。この一巡を最低限の実装で通す。

複数のセッションで進めるための作業メモを兼ねる。タスクを終えたらチェックを付け、決めたことは「決定事項」、セッションの記録は末尾の「作業ログ」に追記する。

## 完了条件（通しのデモ）

1. 起動すると第1ターンの戦略フェーズ。プレイヤーはカルタ書院
2. フルーエン（P012）を選ぶと、都市ウィンドウの「騎士」タブに所属する4人が出る
3. 「侵攻」→ 隣接する他勢力の都市が強調される → アンバリア（P004、レオニス帝国）を選ぶ → 騎士を2人選んで予約
4. 予約が一覧と地図（街道の強調）に出る。取り消せる
5. 「ターン終了」→ CPU 7勢力の戦略フェーズ（何もしない）→ 行軍フェーズ。軍団マーカーがフルーエンからアンバリアへ進む
6. 到着すると戦闘シーン。P004–P012 の戦闘マップのうち、アンバリア側の範囲が表示され、攻守の勢力と騎士が出る
7. デバッグボタンで「攻撃側の勝利」を選ぶ → 戦闘結果画面 → 戦略シーンに戻る
8. アンバリアがカルタ書院の紋章・名前に変わり、侵攻した騎士はアンバリア所属に、守っていた騎士はレオニス帝国の隣接拠点へ退却している
9. 第2ターンの戦略フェーズになる
10. 「防衛側の勝利」の場合は、侵攻した騎士がフルーエンへ戻り、所属は変わらない

## スコープ

含む:

- ターンとフェーズの進行（戦略フェーズ: プレイヤー → CPU各勢力、行軍フェーズ: 全勢力の予約をまとめて解決）
- 騎士（キャラクター）の所属の内部表現と、都市ウィンドウでの表示
- 侵攻予約のUI（出発拠点 → 目標 → 騎士の選択 → 予約一覧・取消）
- 行軍フェーズの演出（既存の行軍マーカー）と戦闘の順次呼び出し
- 戦闘シーン（戦闘マップの表示とデバッグ用の勝敗ボタンのみ）
- 戦闘マップの選択と、map-editor での街道マップ・侵攻方向ごとの範囲の設定
- 戦闘結果画面と、結果の反映（拠点の所属・騎士の移動）
- 都市の所属が変わったときの地図の紋章・名前の更新

含まない（後続のマイルストーン）:

- 内政コマンド（戦略フェーズの枠だけ用意する）
- CPUの思考（M001 のCPUは何もしない）と防衛戦
- 複数拠点からの合流侵攻（最終的には対応する。データ構造だけ拡張しやすくしておく）
- 戦闘の中身（battle-editor の戦闘規則の移植、部隊の配置、兵数）
- 捕縛・登用・在野の人物の扱い（在野という状態だけ持つ）
- 勝利・敗北条件、セーブ・ロード、勢力選択画面
- 全街道分の戦闘マップ（M001 で作るのは P004–P012 の1枚。無い街道はフォールバックのマップを使う）
- 行軍にかかる日数（隣接する拠点へは1ターンで着く）

## 決定事項

| 項目 | 決定 |
| --- | --- |
| ターンの構造 | 1ターン = 戦略フェーズ（プレイヤー → CPU各勢力の順に予約）→ 行軍フェーズ（全勢力の予約をまとめて解決） |
| CPU | M001 では何もしない（順番は回る） |
| 1回の侵攻 | 1つの出発拠点から1人以上の騎士。目標は街道でつながる他勢力の拠点 |
| 出撃できる人物 | 種別（騎士・魔法使い・狩人・政治家・学者）に関わらず全キャラクター。UI上はまとめて「騎士」と呼ぶ |
| プレイヤー勢力 | 定数で既定値を持ち、`?faction=<id>` で切り替え。既定は `carta`（カルタ書院） |
| 戦闘マップの範囲 | 街道ごとの A–B マップ上に、侵攻方向ごとの固定サイズの矩形 |
| 戦後処理（仮） | 攻撃側の勝利: 拠点の所属が攻撃側に変わり、攻撃した騎士が入城。守っていた騎士は隣接する自勢力の拠点へ退却し、無ければ在野になる。防衛側の勝利: 攻撃した騎士は出発拠点へ戻る |

既定の勢力をカルタ書院にしたのは、フルーエン（P012）に4人の騎士がいて、隣のアンバリア（P004、騎士1人）へすぐ侵攻でき、battle 側に `fluen.json`（フルーエン近郊）があるため。

## 設計

### ターンとフェーズ

```
turn N
  strategy フェーズ
    プレイヤー: 侵攻予約（内政はM001ではなし）→「ターン終了」
    CPU各勢力: FACTION_LIST の順に、何もしない（HUDに手番を短く表示するだけ）
  march フェーズ
    全勢力の予約を勢力の手番順に1件ずつ解決
      行軍の演出（出発 → 目標）→ 戦闘シーン → 結果画面 → 反映 → 戦略シーンに戻って次の予約
    すべて解決したら turn N+1 の strategy フェーズへ
```

- 行軍フェーズの進み具合（どの予約まで解決したか）はゲームの状態に持ち、戦闘シーンから戻った戦略シーンが続きから再開する
- 解決の直前に予約を検証し直す（目標がすでに自勢力、出発拠点を失った、など）。無効なら騎士を出発拠点へ戻して飛ばす（M001 で起きるのはテスト時だけ）
- プレイヤーが関わらない戦闘（CPU同士）は M002 以降。予約の解決は勢力に依らない処理にしておき、戦闘を「シーンで行う」か「自動で解決する」かを差し替えられるようにする

### ゲームの状態

置き場所はルートの `src/game/`。React から独立した純粋な関数（状態 → 新しい状態）と、それを保持するストアに分ける。ストアは `SceneManager` より上（`App`）に置き、シーンを切り替えても残す。

```ts
type FactionId = string   // FACTION_LIST の id
type CityId = string      // 'P000'..'P030'
type CharacterId = string // '001'..

interface GameState {
  turn: number
  phase: 'strategy' | 'march'
  /** 戦略フェーズの手番の勢力（march フェーズでは null） */
  activeFaction: FactionId | null
  playerFaction: FactionId
  /** 都市の現在の所属（初期値は CITY_LIST の belongTo） */
  cityOwners: Record<CityId, FactionId>
  characters: Record<CharacterId, CharacterState>
  /** このターンの侵攻予約 */
  orders: InvasionOrder[]
  /** march フェーズで解決中の予約と戦闘 */
  march: { queue: string[]; current: Battle | null } | null
  /** 直近の戦闘の結果（結果画面で表示） */
  lastBattle: BattleReport | null
}

interface CharacterState {
  /** 所属都市。在野なら null */
  cityId: CityId | null
  /** 所属勢力。在野なら null */
  factionId: FactionId | null
}

interface InvasionOrder {
  id: string
  factionId: FactionId
  from: CityId      // M001 は1拠点。合流侵攻では騎士ごとに出発拠点を持つ形に広げる
  to: CityId
  knights: CharacterId[]
}

interface Battle {
  id: string
  orderId: string
  attacker: { factionId: FactionId; from: CityId; knights: CharacterId[] }
  defender: { factionId: FactionId; knights: CharacterId[] }
  cityId: CityId
}

interface BattleReport {
  battle: Battle
  winner: 'attacker' | 'defender'
  /** 反映の結果（結果画面で表示） */
  cityCaptured: boolean
  moves: { characterId: CharacterId; from: CityId | null; to: CityId | null }[]
}
```

- 予約の条件: 戦略フェーズで手番が自勢力・出発拠点が自勢力・目標が `ROAD_LINKS` でつながる他勢力の拠点・騎士は出発拠点に所属し1人以上・1人の騎士は1件の予約にだけ入る・同じ目標への予約は1件まで（合流侵攻は M002 以降）
- 出発拠点の騎士を全員出してもよい（拠点は空になるが所属は変わらない）
- 守る騎士がいない拠点にも侵攻できる（戦闘は起きる。勝敗はデバッグボタンで決める）
- 隣接の判定は地図のインスタンス（`map.network`）ではなく `ROAD_LINKS` から作る。ゲームの状態は地図が無くてもテストできるようにする
- キャラクターのマスターデータ（名前・種別・能力値・画像の位置・略歴）は旧実装から `src/data/` に移す。所属だけを `CharacterState` に分ける
- 退却先が複数あるときは、`ROAD_LINKS` の隣接のうち最初に見つかった自勢力の拠点（決定的にしておく）

### シーンの遷移

```
strategy ──(march: 戦闘の発生)──▶ battle ──(デバッグボタン)──▶ battleResult ──▶ strategy（march の続き）
```

- `SceneParams` に `battle: { battleId: string }` と `battleResult: { battleId: string }` を追加する。中身はストアから読む
- 戦闘シーンの勝敗ボタンで結果をストアに反映し（`resolveBattle`）、その `BattleReport` を結果画面が表示する
- 戦略シーンに戻ったら、カメラを戦闘のあった都市に合わせる（`focusPlace(id, true)`）
- 戦略シーンへ戻るたびの地形の作り直しは、norden-strategy 側で生成結果（`WorldData`）をモジュールにキャッシュして避ける

### 侵攻予約のUIフロー

1. 自勢力の都市を選ぶ。`CityWindow` に「騎士」タブを追加（所属キャラの顔・名前・種別・領主か・予約中か）
2. 都市ウィンドウ（またはコマンドバー）の「侵攻」。押せるのは: 戦略フェーズでプレイヤーの手番・自勢力の都市・予約していない騎士がいる・隣接する他勢力の拠点がある
3. 目標の選択モード: 隣接する他勢力の都市と街道を強調し、ガイド文「侵攻先を選んでください」を出す。強調した都市のクリックで決定、それ以外のクリックは無視。Esc・「やめる」で戻る
4. 騎士の選択ウィンドウ: 出発拠点の予約していない騎士にチェック（1人以上）→「予約」
5. 予約一覧（HUD）: 「出発 → 目標（騎士の人数）」を並べ、各行に取消。予約中の街道は地図上で方向付きに強調し続ける
6. HUD の「ターン終了」で CPU の戦略フェーズへ。予約が0件でも終了できる

HUD（上部）: ターン数・フェーズ・手番の勢力（紋章と名前）。旧実装の `DateBar` を参考にする。

### 戦闘マップ

街道 A–B ごとに、A と B の両方の都市を描いた大きなマップ（A–B マップ）を map-editor で1枚作る。その中に侵攻方向ごとの範囲（固定サイズの矩形）を持つ。範囲は防衛する都市の ID で引く: A→B の侵攻では B を含む範囲 `battleAreas.B`、B→A では `battleAreas.A`。

マップ JSON（version 1 のまま、省略可能なフィールドを追加）:

```json
{
  "version": 1,
  "name": "アンバリア–フルーエン",
  "seed": 3,
  "grid": { "orientation": "flat", "cols": 32, "rows": 20, "hexSize": 1 },
  "cells": [],
  "link": { "cities": ["P004", "P012"] },
  "battleAreas": {
    "P004": { "col": 0, "row": 2 },
    "P012": { "col": 16, "row": 2 }
  }
}
```

- 範囲の大きさは map-runtime の定数 `BATTLE_AREA_SIZE`（仮に 16×16。`fluen.json` と同じ）。エディタとゲームで共有する
- ファイル名は `road-<小さいID>-<大きいID>.json`（例 `road-P004-P012.json`）。ゲームは名前から直接読み込み、`link.cities` で中身を確かめる
- 範囲を切り出す `cropMap(data, area)` を map-runtime の `core/` に置く。セル・人工物・街道を新しい座標に移し、範囲の外へ向かう街道の方向は残す
- オフセット座標の偶奇: flat（odd-q）では列の、pointy（odd-r）では行の開始位置を偶数にしないと、HEX のずれ方が反転する。エディタで偶数に吸着させ、`cropMap` でも検査する
- 地形ノイズはワールド座標で引くため、切り出すと見た目が A–B マップと変わる。切り出し後のデータに元の位置（`origin`）を持たせ、地形生成でノイズを元の座標で引く形を推奨（S5 で確認して決める）
- 該当するマップや範囲が無い街道は、フォールバック（`fluen.json` 全体）を使い、コンソールに警告を出す
