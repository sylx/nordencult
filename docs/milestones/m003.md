# M003: 研究（技術ツリー）

勢力ごとに毎ターン研究ポイントを得て（研究施設と研究担当官から）、研究＞技術の技術ツリーで選んだ技術に注ぎ込み、技術を解禁していく。その一巡を最低限の実装で通す。設計の元は `docs/designs/research_and_artifact_and_so_on.md`。

遺物・探索・法王府は研究と関わるが、M003 では扱わない（後続のマイルストーン）。M002 の残り（成長の演出 S6 など）も後回しにする。

複数のセッションで進めるための作業メモを兼ねる。タスクを終えたらチェックを付け、決めたことは「決定事項」、セッションの記録は末尾の「作業ログ」に追記する。

## 完了条件（通しのデモ）

1. 第1ターン。研究先はまだ無く、研究ポイントも出ていないので、技術画面は勝手に開かない（「研究」＞「技術」で開けば、物理文明・魔法文明の2つが選べ、その子は名前だけ、孫から先は「???」の枠で見える。各技術に画像がある）
2. 「内政」→ 内政画面で、フルーエンの騎士を研究担当官（2人まで）にし、研究の予算をスライダで割り当てると、次のターンの見込み（研究 +x〜y/ターン）が出る
3. 「ターン終了」→ 第2ターン。研究担当官が予算を使って研究ポイントを生むが、研究先が無いのでポイントは宙に浮き、ターンの初めに技術画面が開いて研究先を選ばされる（選ぶまで閉じられず、ターン終了もできない）。選ぶと宙に浮いたポイントがその技術に入る
4. HUD の `FactionBar` に勢力の研究ポイント（/ターン）と、研究中の技術・進捗・完了までのターン数の見込みが出る。次のターンからは研究ポイントが研究中の技術に入り、技術画面で進捗（投入済み / 必要なポイント）が増えていく
5. 図書館を建てると、毎ターンの研究ポイントが増える。研究中の技術が物理文明のものなら、図書館の分が割増になる（魔術学院なら魔法文明）
6. 研究が終わると、次のターンの初めに完成の通知が出て、技術画面が開いて次の研究先を選ばされる（選ぶまでターン終了できない）。終わったターンの余りのポイントは選んだ技術に入る
7. 研究し終えた技術の効果が出る: 物理文明で自勢力の全都市の生産 +5%（都市概要の実効生産に乗る）。技術で解禁される施設が「建てられる施設」に出る
8. 研究し終えた技術の子が研究できるようになり、その子が名前で見えるようになる。前提が複数ある技術（上級魔術師・ガンシップ）は、前提を全部終えるまで研究できない（足りない前提が出る）
9. 研究中の技術を途中で変えられ、それまでの進捗は技術ごとに残る
10. CPU 勢力も研究先を自動で選び、研究施設の分だけ研究が進む（デバッグ表示で確かめる）

## スコープ

含む:

- 技術のマスターデータ（技術ツリー）と norden-data の技術エディタ
- 勢力の研究の状態（研究中の技術・技術ごとの進捗・研究済み・完了の余り）
- 研究ポイントの算出（研究施設と研究担当官）と、研究中の技術への投入（内政処理の中で）
- 研究担当官（内政担当官の新しい役職。予算制）
- 研究施設の効果（`researchPoints`）と、系統（物理・魔法）の割増
- 技術の効果のうち、内政の数値（商業・生産・新兵の練度など）と施設の解禁（`requiredTech`）
- 研究先の選択・変更、完了時に次の研究先を選ばせる流れ
- CPU の研究先の自動選択
- norden-ui: 技術画面（ツリー）、内政画面の研究担当官、`FactionBar` の研究の表示、完成の通知

含まない（後続のマイルストーン）:

- 遺物（アイテムボックス・解析・修復・生産・解体）。遺物の解析・生産には研究ポイントを使わない（設計資料から変更）ので、研究ポイントの使い道は後続でも技術だけ
- 探索（パーティー・ダンジョン）と、戦闘の勝利・遺跡探索による研究ポイントの獲得
- 法王府との友好度と、研究を進めたことによる弾圧
- 技術の効果のうち、戦闘（一斉攻撃・騎兵の移動力・歩兵の攻撃力など）・魔法・遺物の修復と生産に関わるもの。文言としてだけ持つ（施設の `etc` と同じ）
- 魔導書などの装備品と、知力による装備の制限
- CPU の研究担当官の任命と予算（M002 と同じく CPU は担当を割り当てない）

## 決定事項

| 項目 | 決定 |
| --- | --- |
| 研究ポイントの種類 | 1種類（全ツリー共通）。ただし研究施設には系統（物理・魔法）があり、研究中の技術の系統と同じ施設の分は割増（`RESEARCH_BRANCH_BONUS`。仮に +50%）になる。研究担当官の分には系統が無く、割増もない |
| 研究ポイントの出どころ | 研究施設と研究担当官だけ。都市の基礎値は無い（設計資料のとおり）。勢力の都市の合計が勢力の研究ポイントになる |
| 研究ポイントの使い道 | 技術だけ。遺物の解析・生産には使わない（設計資料の「研究＞遺物」への振り分けはやめる） |
| 蓄積しない | 研究ポイントは勢力にためない。毎ターン研究中の技術に入れる。研究先が無いターンに出たポイントは「宙に浮いた」ポイントとして `carry` に持ち、研究先を選んだときにそこへ入れる（ためておけるのは選ぶまでの間だけ）。研究できる技術が残っていなければ消える |
| 研究先 | 勢力ごとに1つ。途中で変えてよく、進捗は技術ごとに残る |
| 研究先を選ばせるとき | 研究ポイントが宙に浮いたとき（研究先が無く `carry` > 0）に、ターンの初めに技術画面を開いて選ばせる。プレイヤーは選ぶまでターン終了できない。第1ターンは研究ポイントがまだ出ていないので選ばせない（研究施設も研究担当官も無いうちに技術画面を突きつけない）。最初に研究ポイントが出たターンが、最初に選ぶターンになる |
| 完了と次の研究先 | CIV のように、研究が終わったら次の研究先を選ばせる。完了は内政処理（ターンの初め）で起き、余りは `carry` に入るので、上の「宙に浮いた」ときと同じ流れになる。余りがちょうど0なら完成の通知だけ出し、次にポイントが出たターンに選ばせる |
| 研究担当官 | 内政担当官の役職 `research` を足す（`OfficerRole`・`FundedRole` に入る）。1役職2人まで、所属の都市だけ、領主はなれない（M002 と同じ）。騎士の種別（学者・魔術師など）による補正は付けない |
| 研究担当官の能力 | 知力だけ（重み `{ intelligence: 1 }`）。2人なら合算（`officerPower`）。設計資料の「知力の合計に応じて」のとおり |
| 研究担当官の金 | 予算制。商業・生産・募兵と同じく、都市の予算（`affairsBudget.research`。0〜1000）から毎ターン 80〜150 の乱数の金を使い、研究ポイント = 消費 × X/100 × `GROWTH_COEF_RESEARCH`。予算が無い・担当官がいなければ何もしない |
| 研究ポイントの端数 | 内政値と同じ扱い。研究担当官の分は都市ごとに、商業・生産と同じく端数をその確率で切り上げる（`affairsGrowth` と同じ関数を使う）。研究施設の系統の割増で出る端数も、勢力の合計で同じく確率で切り上げる |
| 技術ツリーの形 | 前提（`requires`）を複数持てる有向非巡回グラフ。根は物理文明・魔法文明 |
| 技術の画像 | 各技術に画像を持つ。施設と同じ大きさ（256×384）のセルのスプライト画像 `src/assets/techs.webp`（大きさは `src/data/techSprite.json`）から、技術エディタでセルを選ぶ（`Tech.sprite`）。元画像の扱いは施設と同じ（`norden-data/techs/sources/` はコミットしない） |
| ベヒーモス | ドラゴン・ゴーレムと同じ扱い。ベヒーモス（ベヒーモスの残骸の修復）→ 人工ベヒーモス（ベヒーモスを遺物なしで生産できる）。文言は仮 |
| 研究できる条件 | 前提を全部研究し終えていること |
| 見え方 | 研究済み・研究できる技術と、前提の1つ以上が研究済みの技術は名前・効果・必要なポイントが見える。それ以外は「???」の枠だけ（枠と線は出す）。根は最初から見える |
| 技術の効果（M003） | 勢力の全都市にかかる内政の補正（`marketPct`・`productionPct`・`growthPct`・`trainingPct`・`recruitMorale` など。施設の効果と同じ種類）と、施設の解禁（施設の `requiredTech`）。それ以外は `etc`（文言だけ） |
| 効果の乗せ方 | 実効値 = 基礎値 × (1 + 領主の補正 + 施設の補正 + 技術の補正)。研究し終えた直後から見込み（`cityOutput`）に乗り、次の内政処理から実際に効く |
| 文明の根の効果 | 物理文明・魔法文明はどちらも生産 +5%（設計資料のとおり。魔法が金に効くのは不自然なため）。両方を終えれば +10% |
| 設計資料の書き損じ | 「人工ゴレーム」は「人工ゴーレム」として入れる。人工ベヒーモスはベヒーモスの子 |
| 兵科の `rifleman`・`artillery` | 設計資料の「専用兵科は設けず装備品にする」と矛盾しない。この兵科は主に傭兵のもので、ライフル兵・砲兵としてしか編成できない（傭兵は編成の枠の外）。遺物（装備品）のライフルは、騎士が装備して自分の部隊を強くする別の仕組み。M003 ではどちらにも触らない |
| 「初期練度+5」 | 新兵の練度 `recruitMorale` +5 と読む（仮） |
| 施設の解禁 | `Building.requiredTech?: string`（技術の id）。勢力がその技術を研究し終えていなければ建てられない（理由を出す）。既存の `requiredRelic` はそのまま |
| 研究ポイントの計算のタイミング | 内政処理（`runEconomy`）の中。担当官の内政のあとに勢力ごとに合計して研究中の技術へ入れる。施設は処理の前の建設済みのもので数える |
| 中立の都市 | 研究ポイントを生まない（勢力が無いので） |
| CPU の研究先 | 研究先が無ければ、研究できる技術のうち必要なポイントが一番少ないもの（同じならデータの順）を自動で選ぶ。完了の余りも同じように入れる |
| 技術画面の置き場所 | 都市コマンドの「研究」＞「技術」で開く全画面のウィンドウ（`WindowFrame`）。探索・遺物は押せないまま |

## 設計

### マスター（`src/data/techs.ts`・`src/data/techData.json`）

```ts
/** 物理文明・魔法文明 */
type TechBranch = 'physical' | 'arcane'

/** 研究し終えた技術が勢力の全都市にかける効果。施設の効果と同じ種類を使う */
type TechEffect =
  | { kind: 'marketPct'; value: number }
  | { kind: 'productionPct'; value: number }
  | { kind: 'growthPct'; value: number }
  | { kind: 'trainingPct'; value: number }
  | { kind: 'recruitMorale'; value: number }
  /** まだゲームに無い効果（一斉攻撃の解禁、壊れたライフルの修復など）。文言だけ */
  | { kind: 'etc'; value: string }

interface Tech {
  id: string
  name: string
  description: string
  branch: TechBranch
  /** 研究に必要なポイント */
  cost: number
  /** 前提の技術（全部要る）。根は空 */
  requires: string[]
  effects: TechEffect[]
  /** src/assets/techs.webp での画像の左上（ピクセル。大きさは techSprite.json）。施設の sprite と同じ */
  sprite?: { x: number; y: number }
}
```

- ツリーの描画の位置はデータに持たず、`requires` から段（前提からの最長の深さ）と並びを求める（仮。見づらければデータに位置を持たせる）
- 施設の効果の文言 `describeEffect` を技術の効果にも使う
- 最初のデータは設計資料のツリーをそのまま入れる（数値は仮）。研究施設の効果は `etc` から `researchPoints` に直す

### 研究の処理（`src/game/research/`）

内政処理の担当官の内政（M002 の手順 3）のあとに `runResearch` を入れる:

1. 勢力ごとに、自勢力の都市の研究施設のポイントを合計する。施設の系統が研究中の技術の系統と同じなら × (1 + `RESEARCH_BRANCH_BONUS`)
2. 研究担当官の生んだポイント（都市ごとに、予算から使った金 × X/100 × `GROWTH_COEF_RESEARCH`。端数は確率で切り上げ）を足す。施設の割増の端数も確率で切り上げる
3. 研究中の技術があれば `progress` に足す。`cost` に届いたら `researched` に入れ、`current` を null に、余りを `carry` に入れ、`techCompleted` の出来事を積む。研究中の技術が無ければ `carry` に足す（研究できる技術が残っていなければ消える）
4. CPU 勢力は、`current` が null なら研究先を自動で選び、`carry` を入れる（`chooseResearchForCpu`）

関数（純粋な関数。画面の見込みと共有する）:

- `researchOutput(state, factionId, techId?)`: 次のターンの研究ポイントの見込み（施設・担当官の内訳、担当官の分は乱数の幅で x〜y）。`techId` で系統の割増を変えた見込み
- `techStatus(state, factionId, techId)`: `'researched' | 'available' | 'visible' | 'hidden'`（研究済み・研究できる・名前だけ見える・???）
- `researchProblem(state, factionId, techId)`: 研究できない理由（「前提の技術（火魔法）が要ります」など）
- `setResearch(state, factionId, techId)`: 研究先を決める・変える。`carry` があればその技術に入れる（入れて届けば、その場で完了にせず次の内政処理で完了にする。仮）
- `researchTurns(state, factionId, techId)`: 完了までのターン数の見込み
- `techBonus(state, factionId)`: 研究し終えた技術の効果の合計（`cityOutput` が施設の補正と同じように使う）
- `mustChooseResearch(state, factionId)`: 研究ポイントが宙に浮いているか（研究先が無く `carry` > 0 で、研究できる技術が残っている）。ターン終了を止め、ターンの初めに技術画面を開く

定数は `src/game/economy/balance.ts` に足す（`GROWTH_COEF_RESEARCH`・`RESEARCH_BRANCH_BONUS`）。

### UI（norden-ui）

- **技術画面**（`TechScreen`）: 全画面のウィンドウ（`WindowFrame`）。物理文明・魔法文明のツリーを左から右へ（段ごとに列）描き、前提を線でつなぐ。ノードは技術の画像と名前で、研究済み・研究中（進捗のバー）・研究できる・名前だけ・???（画像も伏せる）で描き分ける。選ぶと右に詳細（画像・説明・効果・必要なポイント・完了までのターン数の見込み・足りない前提）と「研究する」。上部に勢力の研究ポイント（/ターンと内訳）と宙に浮いたポイント（`carry`）
  - 選択必須の状態（研究ポイントが宙に浮いたとき）では閉じられず、「研究先を選んでください（宙に浮いた研究ポイント n）」と出す
- **内政画面**: 内政担当官に「研究」の役職（知力、予算あり。説明「予算を使い、研究ポイントを生む」）を足す。見込みは「研究 +x〜y/ターン（金 80〜150）」
- **`FactionBar`**: 研究ポイント（/ターン）と、研究中の技術の名前・進捗・残りターン。研究先が無ければ「研究先なし」（研究ポイントが出ていなければ目立たせない）。押すと技術画面
- **完成の通知**: 新しいターンの初めに `techCompleted` を通知（`events` の仕組み）にし、そのあと研究ポイントが宙に浮いていれば技術画面を選択必須で開く
- **都市概要・内政画面の施設**: 研究施設の効果（研究 +10 など）と、技術で解禁されていない施設の理由
- 画面の追加は `norden-ui/docs/screens.md` の手順に従い、カタログ（デモ）にも載せる

## タスク
