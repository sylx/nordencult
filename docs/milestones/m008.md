# M008: CPU の思考（処理の抜き出し・1 手読み・作戦・性格と難易度）

norden-battle の戦闘で、軍を CPU に任せられるようにする。CPU は部隊ごとに行動の候補を並べて点数を付け、一番いいものを選ぶ（1 手読み）。軍全体の作戦・部隊の騎士の性格・難易度で手が変わる。

いまの戦闘の処理は、状態を変える部分（移動の確定・迎撃・攻撃・退却・番の始まりと終わり・決着）が `BattleApp`（`app.ts`）の演出と絡み合っていて、描画なしでは動かせない。CPU どうしを描画なしで何度も戦わせて確かめるために、**最初にこの処理を描画から抜き出す**。抜き出した処理は、CPU の番のスキップと対戦シミュレータでも使う。

M007 から持ち越したもののうち、M008 で扱うのは CPU の思考だけ。効果音と対戦でのバランス調整は別のマイルストーンにする（バランス調整に使う対戦シミュレータは M008 で作る）。

## 完了条件（通しのデモ）

battle-editor（`npm run dev:battle`）で:

1. 軍ごとに CPU に任せるか（と難易度）を選べる。両方の軍を CPU にすると、最後まで勝手に戦う
2. CPU の番は、プレイヤーと同じ演出（カメラ・攻撃の演出・セリフ）で 1 部隊ずつ進む。CPU の番は早送りとスキップができ、演出の速度はプレイヤーの行動も含めて設定で変えられる（戦闘の途中でも変えられる）
3. CPU はすべての種類の行動（移動・攻撃・一斉攻撃・突撃・魔法・範囲攻撃・迎撃の構え・待機・鼓舞・退却）から選ぶ
4. 明らかにおかしい手を打たない（味方を大きく巻き込む範囲攻撃・意味の無い往復・反撃で自分だけ壊滅する攻撃・軍団長を敵の前に放り出すなど）
5. CPU は兵種に合わせて前後を考えて配備する。攻撃側は拠点を目指して入城を狙い、防衛側は拠点を守る。軍団長は守り、相手の軍団長は狙う
6. 部隊を率いる騎士の性格（猛進・慎重・勇敢・実利）で手の好みが変わる
7. 難易度（易しい・普通・難しい）で強さが変わる。CPU 側の数値は変えない（ズルはしない）

コマンドラインで:

8. `npm run sim`（仮）で、描画なしで CPU どうしを何度も戦わせ、勝率・決着の理由・ターン数・兵種ごとのダメージを表に出せる。シードを固定すれば同じ結果になる
9. 抜き出しの前後で、戦闘の決まり（ダメージ・迎撃・捕縛・決着など）が変わっていない（テストと、ユーザーが遊んでの確認）

## 決定事項

### 方針（2026-11-08 にユーザーと決めたもの）

- **範囲は CPU の思考だけ**。効果音・バランス調整は別のマイルストーン
- **最初に処理を抜き出す**。描画なしで CPU どうしを大量に戦わせられるようにしてから CPU を作る
- **強さは難易度と性格で味付けする**。1 手読みの貪欲な AI を土台にし、そのうえで難易度と性格で手を変える
- **難易度は判断の質だけで差を付ける**。CPU 側の兵数・士気などにボーナスは付けない。易しいほど点数にノイズを入れ、考える要素（危険な HEX・狙いの集中・連携など）を減らす
- **性格は部隊を率いる騎士の性格タグで決める**。ゲームの騎士の `personality` のうち「行動・戦闘スタイル」の軸（`aggressive` 猛進・`cautious` 慎重・`valiant` 勇敢・`pragmatic` 実利）を使う（2026-11-08 の時点で 130 人の全員に何かの性格が付いていて、この軸はそれぞれ 28・47・20・20 人）。軍全体の作戦は軍団長の性格で決める。この軸のタグが無い騎士・騎士のいない部隊は標準
- **シミュレータはコマンドラインで回す**（npm スクリプト。Node で動くので、エンジンと CPU は three.js などの描画の処理を読み込まない作りにする）
- **見せ方はプレイヤーと同じ演出に、早送り・スキップと速度の設定を付ける**。CPU の番は早送り（演出を速くする）とスキップ（演出なしで番を終える）ができる。演出の速度はプレイヤーの行動も含めて設定で変えられる
- **戦闘はいつも赤（防衛側）と青（攻撃側）の 2 軍**。第三の軍は無いので、CPU は赤と青だけを考える（コードにある `green` は扱わない）
- **CPU の配備は兵種に合わせて前後を考える**（いまの `autoDeploy` のままにしない）。前に出す兵種（騎兵・重歩兵など）と後ろに置く兵種（弓兵・魔術師・砲兵など）、軍団長の置き場所を考える
- **演出の速度は `BattleApp` に渡す**（ゲームの設定から渡せるように）。戦闘の途中でも変えられるようにする

## 設計

段階 0 の初め（M008-01）に、型と関数の分け方をここに書いてから相談する。以下はたたき台。

### 処理の抜き出し（段階 0）

いまの作り:

- 評価に使う関数（`moveRange`・`attackRange`・`attackForecast`・`areaCells`・`chargeLanding`・`interceptorsAt` など）は、すでに `HexMap` と `UnitStatus` を受け取るだけの関数になっている（`combat.ts`・`movement.ts` など。three.js を読み込まない）
- 状態を変える処理は `BattleApp` の中にある。`execute` が `Phase`（walk・strike・intercept・retreat）の並びを作り、`nextPhase`・`stepWalk`・`stepIntercept`・`stepStrike`・`stepRetreat` が毎フレームの演出の途中で `commitWalk`・`applyIntercept`・`applyAttack`・`finish`・`judge` を呼んで状態を書き換える。番の始まりと終わり（`startTeamTurn`・`endTurn`・`finishTurn`・`stepSalvo`・`nextAuto`・`passTurn`）も同じ
- 乱数は `Math.random` を直に呼んでいる（ダメージのブレ・捕縛・状態異常・鼓舞・混乱の移動・施設の目標・セリフ）

抜き出し方（案）: **段階ごとの関数にする**。

- 状態を 1 つにまとめる: `BattleState`（`map`・`statuses`・`turn`・いまの軍・`stronghold`・施設・倒れた軍団長・`retreated`・`wipedOut`・`judged`・`outcome`・`rout`）
- 乱数を外から渡す: `Rng`（シードで再現できるもの）。セリフ・演出の乱数は描画の側なので別にしてよい
- 状態を変える処理を、`BattleState` と `Rng` を受け取って状態を書き換え、結果（いまの `ExecuteReport`・`InterceptReport`・`FacilityReport` などと同じもの）を返す関数にする。例:
  - `planPhases(state, plan, end)`: 実行の段階の並び（迎撃で区切る）
  - `commitMove(state, plan, to)`・`resolveIntercept(state, …, rng)`・`resolveStrike(state, plan, rng)`・`resolveRetreat(state, plan, to, rng)`・`finishAction(state, plan, report, end, rng)`
  - `startTeamTurn(state, team)`・`facilityShots(state, side, rng)`・`confusedMoves(state, rng)`・`passTurn(state)`・`judge(state, ended)`
- `app.ts` は、いまと同じ演出の拍子でこの関数を呼ぶだけにする（当たりの瞬間に `resolveStrike` を呼び、返った結果で数字を出す）
- 描画なしで回すときは、同じ関数を待たずに順に呼ぶ（`runAction(state, plan, end, rng)`・`runTurn` など）。CPU の番のスキップとシミュレータで使う

「先にすべて計算してから演出を再生する」作りにはしない。演出の途中の画面（歩いている途中のユニットの位置・兵数の数字）を、計算済みの状態とは別に持つ必要が出て、`app.ts` を大きく書き直すことになるため。

確かめ方: 抜き出しの前に、いまの振る舞いを決めるテスト（シードを固定した乱数で、決まった行動の並びを流したときの兵数・位置・決着）を書いておき、抜き出しの後も同じになることを確かめる。

### CPU の思考（段階 1〜3）

- **口**: `decide(state, unit, ctx) → Action`。`Action` は予約（`Plan` の移動と攻撃）と終わり方（決定・迎撃の構え・待機・鼓舞・退却）。`ctx` は軍の作戦・難易度・性格。CPU は状態を読むだけで書き換えない
- **番の流れ**: 番の初めに軍の作戦を立て（`planTeam(state, team, ctx)`）、動かす順を決め、部隊ごとに `decide` して、プレイヤーと同じ予約・決定の流れで実行する。1 部隊が動くたびに盤面が変わるので、次の部隊はそのつど決め直す
- **候補**: 移動先（`moveRange`）× 攻撃（`attacksOf`。クールタイム中は除く）× 目標・狙う HEX（`aimCells`）× 攻撃の後の移動（残りの行動力）、それに迎撃の構え・待機・鼓舞・退却
- **点数**: 予測（`attackForecast` の期待値）から、与えるダメージ・受ける反撃・殲滅・捕縛・士気・味方の巻き添え、移動先の危険（次の敵の番に受けそうな攻撃・迎撃の構えの射程）・地形の守り・作戦の目標への近さ、を重み付きで足す
- **配備**: 配備の HEX のうち、敵（攻撃側なら拠点、防衛側なら攻撃側の配備の HEX）に近い列に前に出る兵種を、遠い列に後ろに置く兵種を置く。軍団長は後ろ寄りで守りの良い地形。射程のある兵種は前の兵種のすぐ後ろ
- **軍の作戦**: 攻撃側は拠点へ向かって入城を狙う、防衛側は拠点の周りを固める。軍団長は危険な HEX に出さない。相手の軍団長・弱った部隊に狙いを集める
- **性格**（段階 3 の前に中身を相談する。案）:
  - 猛進（aggressive）: 与えるダメージを重く見て、受けるダメージと危険を軽く見る。前に出る。退却しない
  - 慎重（cautious）: 受けるダメージと危険を重く見る。守りの良い地形・迎撃の構え・鼓舞を好み、早めに退却する
  - 勇敢（valiant）: 強い相手・軍団長を狙う。弱った味方の前に出て守る
  - 実利（pragmatic）: 殲滅・捕縛できる相手を狙う。受けるものに対して与えるものの効率を見る
- **難易度**: 易しい・普通・難しい。易しいほど点数にノイズを入れ、考える要素を減らす（易しいは危険な HEX と狙いの集中を見ない、など）。CPU 側の数値は変えない
- **性能**: 候補は部隊ごとに数百〜数千。予測の計算は軽いので、まずはそのまま全部数える。重ければ移動先を絞る

### 演出の速度・早送り・スキップ（段階 1）

- 演出の時間（歩く・攻撃・カメラ・セリフ・施設の射撃）に倍率を掛ける。設定の速度はプレイヤーの行動にも効く。CPU の番の早送りは、その上にさらに倍率を掛ける
- 速度は `BattleApp` を作るとき（または `loadMap`）に渡し、戦闘の途中でも変えられるようにする（`BattleApp.setSpeed` など）。演出の途中で変わっても、残りの時間から速さが変わるだけで途切れない作りにする。画面のどこで変えるか（戦闘中のメニュー・ボタン）は battle-editor で試し、ゲームにつなぐときにルートの設定とつなぐ
- スキップは、CPU の番の残りを抜き出した処理で演出なしに進め、終わったら画面を作り直す

### 対戦シミュレータ（段階 1）

- `npm run sim -- --map <マップ> --runs 100 --seed 1 …`（仮）。マップ・両軍の編成・難易度・回数・シードを渡す
- 出すもの: 勝率・決着の理由（軍団長の全滅・退却・入城・時間切れ）・ターン数・兵種ごとの与えた/受けたダメージ・止まった戦い（ターンの上限に届いた）の数
- 編成はとりあえず battle-editor の保存形式（JSON）を読む
