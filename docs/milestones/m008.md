# M008: CPU の思考（処理の抜き出し・1 手読み・作戦・性格と難易度）

norden-battle の戦闘で、軍を CPU に任せられるようにする。CPU は部隊ごとに行動の候補を並べて点数を付け、一番いいものを選ぶ（1 手読み）。軍全体の作戦・部隊の騎士の性格・難易度で手が変わる。

いまの戦闘の処理は、状態を変える部分（移動の確定・迎撃・攻撃・退却・番の始まりと終わり・決着）が `BattleApp`（`app.ts`）の演出と絡み合っていて、描画なしでは動かせない。CPU どうしを描画なしで何度も戦わせて確かめるために、**最初にこの処理を描画から抜き出す**。抜き出した処理は、CPU の番のスキップと対戦シミュレータでも使う。

M007 から持ち越したもののうち、M008 で扱うのは CPU の思考だけ。効果音と対戦でのバランス調整は別のマイルストーンにする（バランス調整に使う対戦シミュレータは M008 で作る）。

複数のセッションで進めるための作業メモを兼ねる。タスクを終えたらチェックを付け、決めたことは「決定事項」、セッションの記録は末尾の「作業ログ」に追記する。

## 完了条件（通しのデモ）

battle-editor（`npm run dev:battle`）で:

1. 軍ごとに CPU に任せるか（と難易度）を選べる。両方の軍を CPU にすると、最後まで勝手に戦う
2. CPU の番は、プレイヤーと同じ演出（カメラ・攻撃の演出・セリフ）で 1 部隊ずつ進む。CPU の番は早送りとスキップができ、演出の速度はプレイヤーの行動も含めて設定で変えられる（戦闘の途中でも変えられる）
3. CPU はすべての種類の行動（移動・攻撃・一斉攻撃・突撃・魔法・範囲攻撃・迎撃の構え・待機・鼓舞・退却）から選ぶ
4. 明らかにおかしい手を打たない（味方を大きく巻き込む範囲攻撃・意味の無い往復・反撃で自分だけ壊滅する攻撃・軍団長を敵の前に放り出すなど）
5. CPU は兵種に合わせて前後を考えて配備する。攻撃側は拠点を目指して入城を狙い、防衛側は拠点を守る。軍団長は守り、相手の軍団長は狙う
6. 部隊を率いる騎士の性格（猛進・慎重・勇敢・実利）で手の好みが変わる
7. 難易度（易しい・普通・難しい）で強さが変わる。CPU 側の数値は変えない（ズルはしない）

コマンドラインで:

8. `npm run sim`（仮）で、描画なしで CPU どうしを何度も戦わせ、勝率・決着の理由・ターン数・兵種ごとのダメージを表に出せる。シードを固定すれば同じ結果になる
9. 抜き出しの前後で、戦闘の決まり（ダメージ・迎撃・捕縛・決着など）が変わっていない（テストと、ユーザーが遊んでの確認）

## 決定事項

### 方針（2026-11-08 にユーザーと決めたもの）

- **範囲は CPU の思考だけ**。効果音・バランス調整は別のマイルストーン
- **最初に処理を抜き出す**。描画なしで CPU どうしを大量に戦わせられるようにしてから CPU を作る
- **強さは難易度と性格で味付けする**。1 手読みの貪欲な AI を土台にし、そのうえで難易度と性格で手を変える
- **難易度は判断の質だけで差を付ける**。CPU 側の兵数・士気などにボーナスは付けない。易しいほど点数にノイズを入れ、考える要素（危険な HEX・狙いの集中・連携など）を減らす
- **性格は部隊を率いる騎士の性格タグで決める**。ゲームの騎士の `personality` のうち「行動・戦闘スタイル」の軸（`aggressive` 猛進・`cautious` 慎重・`valiant` 勇敢・`pragmatic` 実利）を使う（2026-11-08 の時点で 130 人の全員に何かの性格が付いていて、この軸はそれぞれ 28・47・20・20 人）。軍全体の作戦は軍団長の性格で決める。この軸のタグが無い騎士・騎士のいない部隊は標準
- **シミュレータはコマンドラインで回す**（npm スクリプト。Node で動くので、エンジンと CPU は three.js などの描画の処理を読み込まない作りにする）
- **見せ方はプレイヤーと同じ演出に、早送り・スキップと速度の設定を付ける**。CPU の番は早送り（演出を速くする）とスキップ（演出なしで番を終える）ができる。演出の速度はプレイヤーの行動も含めて設定で変えられる
- **戦闘はいつも赤（防衛側）と青（攻撃側）の 2 軍**。第三の軍は無いので、CPU は赤と青だけを考える（コードにある `green` は扱わない）
- **CPU の配備は兵種に合わせて前後を考える**（いまの `autoDeploy` のままにしない）。前に出す兵種（騎兵・重歩兵など）と後ろに置く兵種（弓兵・魔術師・砲兵など）、軍団長の置き場所を考える
- **演出の速度は `BattleApp` に渡す**（ゲームの設定から渡せるように）。戦闘の途中でも変えられるようにする

#### いまの作り

- 評価に使う関数（`moveRange`・`attackRange`・`attackForecast`・`attackResult`・`areaCells`・`splashUnits`・`chargeLanding`・`interceptorsAt`・`judgeBattle` など）は、すでに `HexMap` と `UnitStatus` を受け取るだけの関数になっている（`combat.ts`・`movement.ts`・`victory.ts` など）。ルールのモジュールはどれも three.js を読み込まない（読み込むのは app.ts と演出・UI だけ）
- 状態を変える処理は `BattleApp` の中にある:
  - 行動: `execute` が `ExecuteReport` と段階（walk・strike・intercept・retreat）の並びを作る → `nextPhase` が段階を 1 つ取り出す（歩く段階は、そのときの盤面で迎撃の射程に入る HEX で区切って迎撃の段階を挟む）→ 毎フレームの `stepWalk`・`stepStrike`・`stepIntercept`・`stepRetreat` が、着いた・当たった瞬間に `commitWalk`・`applyAttack`（＋`applySplash`・`inflict`・`wipeOut`・`plowCell`）・`applyIntercept`（＋`halt`）を呼ぶ → 段階が尽きたら `finish`（行動力・待機・鼓舞・迎撃の構え・壊滅したユニットを除く・記録・軍団長の喪失）→ `judge`
  - 番: `startBattle`・`startTeamTurn`（`refreshTeam`・入城の決まりの印・魔導台・凍結）・`endTurn`（混乱したユニットを 1 部隊ずつ `nextAuto` で動かす）→ `finishTurn`（番を終えた軍の入城の判定・施設が撃つか）→ `stepSalvo`（`facilityTargets`・`applyFacilityShot`）→ `passTurn`（状態の残りターン・次の軍・ターンの数）
  - 決着: `judge` → 強制退却（`rout`。部隊ごとにプレイヤーが退却先を選ぶ）→ `endBattle`
  - 行動済みの判定（`refreshMarks` の `done`）は `canAct(menuContext(…))` で、入城の判定（行動を終えたか）にも使う
- ゲームの乱数は `Math.random` を直に 7 か所で呼んでいる: ダメージのブレ（`randomRoll`。攻撃・反撃・巻き添え・迎撃・施設）、退却の失敗、殲滅の捕縛、状態異常、鼓舞の回復量、混乱の移動先、施設の目標。セリフ（`bark`・`exchange`・`barks.ts` の行選び）の乱数は演出の側
- 壊滅したユニットがマップから消えるのは行動の終わり（`finish`）。それまでは盤面に残っていて、捕縛の「隣接している敵」に数えられ、足止めで戻る道もふさぐ。抜き出しでは、こういう順番もそのまま残す

#### 抜き出し方: 段階ごとの関数（`battle-runtime/src/engine/`）

「先にすべて計算してから演出を再生する」作りにはしない（演出の途中の画面を計算済みの状態と別に持つことになり、app.ts を大きく書き直すため）。
いまの段階の区切りのまま、状態を変える部分だけを関数にして、`app.ts` は演出の拍子（着いた・当たった瞬間）でそれを呼ぶ。描画なしで回すときは同じ関数を待たずに順に呼ぶ。
乱数を引く順番が同じなので、同じシードなら演出ありと描画なしで同じ結果になる。

engine は three.js・React・DOM を読み込まない。パッケージに入口を足し（`@norden/battle-runtime/engine`）、Node のシミュレータからはそこだけを読む（いまの `index.ts` は `BattleApp` を読み込むので使えない）。

`BattleState`（いま `BattleApp` のフィールドに散らばっているもの）:

```ts
interface BattleState {

  statuses: Map<UnitData, UnitStatus>;
  turn: number;
  activeTeam: TeamId;
  stronghold: Offset | null;
```

`BattleApp` は `state` を 1 つ持ち、いまの公開しているフィールド（`statuses`・`turn`・`activeTeam`・`stronghold`・`retreats`・`facilities`・`retreated`・`wipedOut`・`outcome`・`routing`）は `state` へのゲッター（とセッター）にして、BattleScreen・battle-editor・ゲームからの使い方は変えない。
演出と操作の状態（選択・`targeting`・`exec` の演出の部分・`salvo` の演出・`autoQueue` の時刻・カメラ）は app.ts に残す。

行動の実行（`engine/action.ts`）:

```ts
type ActionEnd = 'confirm' | 'intercept' | 'wait' | 'inspire' | 'retreat';
type ActionPhase =
  | { kind: 'walk'; path: Offset[]; commit: boolean }
  | { kind: 'strike' }
  | { kind: 'intercept'; shooter: UnitData; at: Offset; route: Offset[] }
  | { kind: 'retreat' };
interface ActionRun { plan: Plan; report: ExecuteReport; end: ActionEnd; phases: ActionPhase[]; supporters: UnitData[] }

beginAction(state, plan, end, to, rng): ActionRun | null   // 行えるか確かめ、報告を作り、段階を並べる。迎撃の構えを解く。退却の成否はここで引く
nextPhase(state, run): ActionPhase | null                  // 次の段階（歩かない移動は確定して飛ばす・壊滅した迎撃は飛ばす・歩く段階を迎撃で区切る）。尽きたら null
commitMove(state, run, to): void                           // 歩き終えた HEX へ移動を確定する
resolveIntercept(state, run, phase, rng): InterceptReport  // 迎撃が当たった瞬間（兵数・士気・状態異常・巻き添え・殲滅と捕縛）
afterIntercept(state, run, phase): void                    // 迎撃の演出の後（壊滅なら打ち切り、弓兵なら足止めして戻る道を並べる）
resolveStrike(state, run, rng): AttackReport                // 攻撃が当たった瞬間（攻撃・反撃・状態異常・殲滅と捕縛・巻き添え・耕す・目標の無い攻撃の士気・クールタイム）
afterStrike(state, run): void                              // 攻撃の演出の後（突撃の飛び出しを確定・壊滅なら続きを捨てる）
finishAction(state, run, rng): { removed: UnitData[]; ended: UnitData[] }
                                                           // 行動力・待機・鼓舞・迎撃の構え・足止め、壊滅・退却したユニットを除く、退却と殲滅の記録・軍団長の喪失。
                                                           // ended は入城の判定に渡す「行動を終えたユニット」
runAction(state, plan, end, to, rng): ExecuteReport        // 描画なし: 上を順に呼び、最後に judge まで
```

app.ts の `execute` は `beginAction`、`nextPhase` は engine の `nextPhase` に演出の準備（歩く線・カメラ・セリフ・エフェクト）を足したもの、`stepIntercept` の当たりで `resolveIntercept`、終わりで `afterIntercept`、`stepStrike` の当たりで `resolveStrike`、終わりで `afterStrike`、`finish` は `finishAction` の後に絵の作り直し・選び直し・イベント・`judge` になる。頭上の数字・イベント（`retreat`・`wipeout`・`execute`）は、engine が返した報告から app.ts が出す。

番と決着（`engine/turn.ts`）:

```ts

startTeamTurn(state, team): void                 // 行動力・クールタイム・入城の決まりの印・魔導台・凍結
confusedUnits(state): UnitData[]                 // 番の終わりに勝手に動く混乱したユニット
confusedPlan(state, unit, rng): Plan | null      // ランダムな移動先（動けなければ行動力 0 にして null）。app は 'wait' で実行する

facilityTarget(state, kind, side, rng): UnitData | null
```

描画なしの 1 戦（M008-07）は `engine/sim.ts` に置く（番の終わりを描画なしで進める `runTurnEnd`・強制退却を進める `settle` もここ。強制退却の退却先は打ち手が選ぶため）。打ち手は `(state, unit) => 行動`（予約・終わり方・退却先）を返す関数で、段階 1 の CPU の `decide` もこの形にする。
強制退却の退却先は、描画なしでは打ち手が選ぶ（ランダムな打ち手は最初の拠点）。シードからは「ルールの乱数」と「打ち手の乱数」を別々に作り、打ち手を変えてもルールの乱数の並びがずれないようにする。

#### 確かめ方（M008-02）

いまの `BattleApp` は WebGL の描画を作るので、vitest（Node）では動かせない。そのため「抜き出す前のコードで流すテスト」は書けない。代わりに:

1. 抜き出す前に、app.ts を読んで決まりを 1 つずつテストにする（engine の関数の形で書き、期待値は `attackResult` などのルールの関数と決まった乱数から求める）。範囲: 移動の確定・迎撃（区切り・壊滅で打ち切り・弓兵の足止めと味方のいる HEX からの戻り・壊滅した迎撃は撃たない）・攻撃と反撃・一斉攻撃・突撃の飛び出し・巻き添え・耕す・状態異常・クールタイム（＋1）・殲滅と捕縛（相討ちの相手は数えない・壊滅したユニットは行動の終わりまで盤面に残る）・目標の無い攻撃の士気・鼓舞・待機・迎撃の構え・退却・番の始まり（凍結・魔導台・入城の決まりの印）・混乱の移動・施設・決着の順番・強制退却
2. 抜き出した後に通す
3. 描画なしの 1 戦（M008-07）の結果をシードごとにスナップショットに残し、以後の作り替えで変わらないことを確かめる
4. 最後にユーザーが battle-editor で遊んで、挙動が前と変わっていないか確かめる（M008-08）

### CPU の思考（段階 1〜3）

- **口**: `decide(state, unit, ctx) → Action`。`Action` は予約（`Plan` の移動と攻撃）と終わり方（決定・迎撃の構え・待機・鼓舞・退却）。`ctx` は軍の作戦・難易度・性格。CPU は状態を読むだけで書き換えない
- **番の流れ**: 番の初めに軍の作戦を立て（`planTeam(state, team, ctx)`）、動かす順を決め、部隊ごとに `decide` して、プレイヤーと同じ予約・決定の流れで実行する。1 部隊が動くたびに盤面が変わるので、次の部隊はそのつど決め直す
- **候補**: 移動先（`moveRange`）× 攻撃（`attacksOf`。クールタイム中は除く）× 目標・狙う HEX（`aimCells`）× 攻撃の後の移動（残りの行動力）、それに迎撃の構え・待機・鼓舞・退却
- **点数**: 予測（`attackForecast` の期待値）から、与えるダメージ・受ける反撃・殲滅・捕縛・士気・味方の巻き添え、移動先の危険（次の敵の番に受けそうな攻撃・迎撃の構えの射程）・地形の守り・作戦の目標への近さ、を重み付きで足す
- **配備**: 配備の HEX のうち、敵（攻撃側なら拠点、防衛側なら攻撃側の配備の HEX）に近い列に前に出る兵種を、遠い列に後ろに置く兵種を置く。軍団長は後ろ寄りで守りの良い地形。射程のある兵種は前の兵種のすぐ後ろ
- **軍の作戦**: 攻撃側は拠点へ向かって入城を狙う、防衛側は拠点の周りを固める。軍団長は危険な HEX に出さない。相手の軍団長・弱った部隊に狙いを集める
- **性格**（段階 3 の前に中身を相談する。案）:
  - 猛進（aggressive）: 与えるダメージを重く見て、受けるダメージと危険を軽く見る。前に出る。退却しない
  - 慎重（cautious）: 受けるダメージと危険を重く見る。守りの良い地形・迎撃の構え・鼓舞を好み、早めに退却する
  - 勇敢（valiant）: 強い相手・軍団長を狙う。弱った味方の前に出て守る
  - 実利（pragmatic）: 殲滅・捕縛できる相手を狙う。受けるものに対して与えるものの効率を見る
- **難易度**: 易しい・普通・難しい。易しいほど点数にノイズを入れ、考える要素を減らす（易しいは危険な HEX と狙いの集中を見ない、など）。CPU 側の数値は変えない
- **性能**: 候補は部隊ごとに数百〜数千。予測の計算は軽いので、まずはそのまま全部数える。重ければ移動先を絞る

#### 段階 1 で決めたこと（2026-11-08）

- CPU は `battle-runtime/src/cpu/`（three.js を読み込まない。`@norden/battle-runtime/cpu`）。`cpuPlayer({ difficulty })` が engine の打ち手（`Player`）を作り、
  BattleApp と対戦シミュレータの両方で同じものを使う。打ち手は関数ひとつからオブジェクトに広げた（`decide`・`beginTurn`・`order`・`routTo`）
- 1 手読みの候補は「移動先（その場も）× 攻撃 × 目標」と「移動だけ・その場で待機（待機で行動を終える）」。移動だけの手は待機で終える（同じ番に何度も動き回らない）。
  騎兵の攻撃の後の移動は、攻撃を実行した後にもう一度 decide する
- 点数（`decide.ts`・重みは `weights.ts`）: 攻撃は予測の期待値（与える − 受ける、殲滅・壊滅の見込み、士気の差、巻き添え。兵数は兵種の力で重みを付け、
  軍団長の部隊は 3 倍に重く見る）。位置は敵への近さ（射程のある兵種は射程の端）・攻撃側は拠点への近さ・防衛側は拠点の周り（3 HEX）・
  次の敵の番に攻撃されそうな度合い（`threat.ts`。軽い近似）・地形の守り
- シミュレータで見つけたことから足したもの:
  - 脅威の重みは、前に出る兵種を軽く・射程のある兵種を重く・軍団長はさらに重く（同じ重みだと、敵の射程の手前で止まってにらみ合いになった）
  - 兵力の比: 受けるダメージ・脅威の重みに「敵の兵力 ÷ 味方の兵力」を掛け、敵に近づく重みにはその逆数を掛ける（数で勝る側が押し込む）
  - 膠着: 盤面の兵数の合計が変わらない番が続いたら、慎重さを下げて前に出る
  - 往復しない: 攻撃せずに、前の自分の番の初めにいた HEX へ戻る手は減点する（序盤に歩兵が半歩ずつ出入りしていた）
- 動かす順: 前に出る兵種 → 射程のある兵種 → 軍団長の部隊。同じ組では敵に近い部隊から
- BattleApp の CPU の番: カットインの間は待ち（BattleScreen が `holdCpu` で知らせる）、部隊を選んで予約の矢印を少し見せてから、プレイヤーと同じ演出で実行する。
  CPU が操作している間（CPU の軍の配備・番・強制退却）は人の操作を受け付けず、行動メニューも出さない。CPU の陣営の配備は自動配置
- スキップは、実行中の演出を速く（×40）終わらせてから、番の残り（部隊の行動・混乱の移動・入城の判定・施設の射撃）を engine で続けて行う。
  イベントは演出ありと同じ順に出す（戦闘記録に載る）。人の軍の強制退却になったら、そこで止めて退却先を選ばせる
- 対戦シミュレータは battle-editor に置いた（`battle-editor/sim/`。編成をゲームの騎士のデータで組むため）。Vite の `runnerImport` で TypeScript を動かす（依存は足していない）。
  編成を組む `gameKnights.ts` は three.js を読み込まない口 `@norden/battle-runtime/rules` から値を読むようにした

#### 段階 2 で決めたこと（2026-11-08）

- **考える要素を切れるようにした**（`CpuFeatures`: `allAttacks`・`danger`・`stances`・`strategy`・`deploy`）。すべて切ると段階 1 の CPU（`BASIC_FEATURES`）。
  シミュレータで段階 1 と比べる（`--attacker basic`）・要素ごとの効き目を見る（`--attacker-off danger` など）のに使い、段階 3 の難易度にも使える
- すべての攻撃（M008-16）: 地点を狙う攻撃（メテオ・アーススパイク）・自分が中心の攻撃（乱撃）も候補にする。範囲の味方の巻き添えは 1.5 倍に重く見て、
  味方を壊滅させるならさらに引く。状態異常は「相手の番を止める」として相手の基本攻撃力（`basicAttack`）で見積もる。耕すのは、敵のいる HEX の守りを下げる分と
  城壁を崩す分（攻撃側は足し、防衛側は自分の壁なので引く）。クールタイムのある攻撃は、クールタイム 1 番ごとに得る点数を 12% 割り引く
- 危険な HEX（M008-17。`danger.ts`）: 「攻撃できる敵の数」から「次の敵の番に受けそうなダメージ（兵数）」に変えた。敵ごとに使える攻撃で一番効くもの
  （地形・包囲・迎撃の構えも入る）を、その敵が届く範囲にいる味方の数で割って足す。**軍団長の部隊は敵が狙いを集めるので割らない**
  （割ると、攻撃側の軍団長が敵の前に出て討たれることが段階 1 の 2 倍になった）。殲滅されそうな HEX（受けそうなダメージが兵数の 9 割以上）はさらに引く。
  要塞砲（次の相手の番の終わりに撃つなら、射程にいる味方の数で割る）も足す。移動の途中で迎撃の構えの間接ユニットに撃たれる分を引き、
  弓兵・ライフル兵に足止めされるなら、その手はそこで行動が終わるものとして数える
- 構え・鼓舞・退却（M008-18）:
  - 迎撃の構え: 間接の兵種は、次の敵の番に射程へ入ってきそうな敵に撃つ見込み（＋前に出る敵を止める分）。近接の兵種は、危険の点数のうち構えで減らせる分（35%）。
    攻撃側は攻めないと勝てないので構えの点数を半分に見る。膠着していれば（敵が寄ってこない）下げる
  - 鼓舞: 上がる士気の見込み × 自分の基本攻撃力。攻撃の後の鼓舞は、攻撃で上がる士気の分を除く
  - 部隊ごとの退却（ユーザーと決めた。「部隊ごと＋負けを認める」）: 軍団長でない部隊は、兵数が戦闘の初めの 35% 以下で、どこへ動いても次の敵の番に
    殲滅されそうで、殲滅できる相手もおらず、軍が数で勝っていなければ退却する
  - 負けを認める: 味方の兵力が戦闘の初めの 30% 以下に減り（軍団長の重さを入れない兵力で比べる）、敵が 4 倍以上で軍団長の部隊がどこへ動いても殲滅されそうなとき、
    または敵が 2 倍以上で戦況が 3 番動いていないとき、軍団長の部隊が退却して戦闘を終える（捕縛を避ける・逃げ回って決着しないのを避ける）。
    数だけで認めると、1 手読みの戦いは軍団長を討てば逆転するので勝てた戦いを捨ててしまった（攻撃側の勝率が 81% → 58%）
  - 一斉攻撃は段階 1 から攻撃の候補に入っている（取り囲んだ敵だけ）
- 軍の作戦（M008-19。`strategy.ts`）: 攻撃側は防衛拠点で行動を終えれば入城して勝つ（攻撃した後も、拠点にいれば待機で行動を終える）。
  防衛側は拠点の守りの部隊（拠点にいる部隊。いなければ射程のある・軍団長でない・拠点に近い部隊）を拠点に置き、拠点の隣の敵を重く狙い、
  拠点が空いて隣に敵が来たら塞ぐ。数で勝っていれば拠点の周りに留まる重みを下げて討ちに出る。軍団長の部隊は敵に近づく重みを 0.4 倍にする。
  弱った相手（兵が減った割合）に与えるダメージを割り増して狙いを集める。負けを認めそうなら軍団長の部隊を最初に動かす
- 配備（M008-20。`deploy.ts`）: どの部隊を出すかは編成の上から（自動配置と同じ。編成を組んだ側が決める。兵力で選ぶと兵数の少ない魔術師が外れた）。
  置き方は、配置地点を敵に近い順（攻撃側は防衛拠点、防衛側は攻撃側の配置地点）に並べ（地形の守りは少し前に数える）、前に出る兵種（守りの固い順）→
  射程のある兵種（射程の短い順）を前から置き、軍団長の部隊はその後ろ数列のうち守りの良い・後ろ寄りの HEX。`Player.deploy` で BattleApp とシミュレータの両方が使う
- シミュレータ: `--attacker basic`（段階 1 の CPU）・`--attacker-off`/`--defender-off`（要素を切る）・`--trace`（行動を 1 つずつ出す）を足し、
  決着の理由を勝った陣営ごとに出すようにした。兵種を混ぜた編成 `battle-editor/sim/rosters/mixed.json`（魔法・乱撃・砲兵・ライフル兵が出る）を置いた

#### 段階 3 で決めたこと（2026-11-11。M008-23）

ユーザーと決めた（4 つとも案のとおり）:

- **性格の効き方は案のとおり、はっきり効かせる**（眺めて違いが分かる強さ）。部隊の騎士の性格で、その部隊の点数の重みとしきい値を変える:

  - 実利（pragmatic）: 殲滅（捕縛）の見込み ×1.5・弱った相手を狙う割り増し ×1.5・与える ÷ 受ける の効率が悪い攻撃を減点。退却は兵が 45% 以下から
  - この軸のタグが無い騎士・騎士のいない部隊は標準（段階 2 の CPU のまま）
- **軍団長の性格で軍の作戦も変える**: 全軍の前に出る度合い・防衛側が拠点の周りに留まる広さ・軍団長自身の出方・負けを認めるしきい値。
  各部隊の手の好みは、その部隊の騎士の性格
- **難しい = 段階 2 の CPU（ノイズ無し）＋連携**: 番の中で、後に動く味方で殲滅できる相手を先に削る・殲滅の確率をダメージの幅から見る。
  **普通 = 段階 2 の CPU に小さいノイズ**
- **易しいでも明らかにおかしい手は打たない**: 点数に大きいノイズを入れ、危険な HEX（数だけ見る）・狙いの集中・連携を切る。
  入城・拠点の守り・味方の巻き添えを避ける・軍団長を危ない所に出さない、は残す（完了条件 4 は易しいでも守る）

実装で決めたこと（M008-24〜26。2026-11-11）:

- 性格は部隊の状態に入れた（`UnitStatus.personality`・`TroopInit.personality`。`BattleStyle`・`BATTLE_STYLE_NAMES`・`battleStyleOf` は unitStatus.ts）。
  battle-editor は編成の騎士の `personality` から渡す。部隊の情報（右上の「騎士」）と、部隊の道具の騎士の選択肢に性格を出す。
  ゲーム（ルートの `battleTroops.ts`）から渡すのは、ルートからのつなぎ込みのとき
- 性格の重みは `cpu/temper.ts`（部隊の気質 `Temper`・軍の気質 `ArmyTemper`）。考える要素 `CpuFeatures.personality` で切れる（段階 1 の `basic` は切る）
- 軍団長の部隊と、防衛側の拠点の守りの部隊は、性格の効き（受けるダメージ・危険・前に出る・迎撃の構え）を半分にする（役目を先にする）
- 決めた倍率から変えたもの（シミュレータで見て）:
  - 勇敢・実利の狙いの倍率を強めた（勇敢: 相手の軍団長 ×3・強い相手 0.8・弱った相手 0、実利: 殲滅 ×2・弱った相手 ×2.5・効率は受けるダメージが与える 25% を超えた分）。
    案の倍率では、狙った相手が標準とほとんど変わらなかった（届く相手が 1〜2 部隊なので、小さい割り増しでは選び方が変わらない）
  - 軍の気質（案では数字を出していなかったもの）: 猛進の軍は拠点の周りの重みを 0.8 倍（0.6 倍・広さ 4 では防衛側の勝率が 3 分の 1）、
    勇敢の軍団長の出方は 0.6（0.8 では攻撃側の軍団長を討たれる戦いが 1.7 倍）
- 難易度（`DIFFICULTY_PROFILES`）: 易しいは danger・focus・teamwork を切りノイズ 40 点、普通は teamwork を切りノイズ 10 点、難しいはすべてでノイズ無し。
  ノイズは候補の点数に 0〜ノイズの乱数（打ち手の乱数）を足して選ぶ（一番いい手からノイズより悪い手は選ばない）。
  狙いの集中は `CpuFeatures.focus` として軍の作戦（strategy）から分けた
- 連携（難しい）: 殲滅・壊滅の見込みをダメージの幅から確率で見る、まだ動いていない味方と合わせて殲滅できる相手を削る（殲滅の点数の 4 割）、

- シミュレータ: `--attacker-style`・`--defender-style`（陣営のすべての部隊の性格を差し替える）・`--attacker-noise`・`--defender-noise`、
  陣営ごとの手の傾向の表（敵との距離・攻撃・相手の軍団長を狙った割合・殲滅した数・与えた÷反撃・狙った相手の兵の残り・構え・鼓舞・退却・負けを認めた・
  殲滅された・軍団長を討たれた・兵の損耗）を足した

### 演出の速度・早送り・スキップ（段階 1）

- 演出の時間（歩く・攻撃・カメラ・セリフ・施設の射撃）に倍率を掛ける。設定の速度はプレイヤーの行動にも効く。CPU の番の早送りは、その上にさらに倍率（3 倍）を掛ける
- 実装（2026-11-08）: 演出の時刻をすべて共有の時計（`fxClock.ts`）で測り、BattleApp が毎フレーム速度を掛けて進める（`setTimeout` も時計の予約に置き換えた）。
  足元の輪・状態の印のような繰り返すだけの演出は実時間のまま。battle-editor の「CPU・速度」で ×0.5〜×3 を選べる
- 速度は `BattleApp` を作るとき（または `loadMap`）に渡し、戦闘の途中でも変えられるようにする（`BattleApp.setSpeed` など）。演出の途中で変わっても、残りの時間から速さが変わるだけで途切れない作りにする。画面のどこで変えるか（戦闘中のメニュー・ボタン）は battle-editor で試し、ゲームにつなぐときにルートの設定とつなぐ
- スキップは、CPU の番の残りを抜き出した処理で演出なしに進め、終わったら画面を作り直す
